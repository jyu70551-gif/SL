# 입출고 소진율·증량 검토 (실험 중)

판매량이 늘었는지가 아니라 **준비한 상품이 반복해서 얼마나 소진됐나**를 봅니다. 통계가 신호를 찾고, AI는 근거와 확인 질문만 설명하는 구성입니다. (쉬운 설명과 기준값의 근거는 [stats-guide.md](stats-guide.md) 6장)

## 상태
- 만든 것: 계산 엔진 [stock.py](../backend/app/stock.py), 저장 표 `stock_daily`(마이그레이션 0011), 홈용 요약 주소 `GET /api/stock/summary`([stock_api.py](../backend/app/stock_api.py)), 홈 "집중 관리 식품군" 안의 상품별 소진율·폐기율·신호([StockSignals.jsx](../frontend/src/components/StockSignals.jsx)), 가짜 자료 만들기 [make_stock_data.py](../backend/tools/make_stock_data.py), 랩 DB에 넣기 [load_stock_csv.py](../backend/tools/load_stock_csv.py), 시험 [test_stock.py](../backend/tests/test_stock.py)
- 안 만든 것: 입출고 파일 올리기 화면, AI 문장. 실제 자료를 받을 수 없어 형식을 가정하고 시작했습니다. 시연 DB에는 `load_stock_csv.py`로 가짜 자료를 넣습니다.
- **Supabase에는 `alembic upgrade head`(0008~0011)를 직접 실행해야 합니다.** `stock_daily`를 필수 표로 확인하므로 실행 전에는 서버가 시작되지 않습니다(0008~0010도 같습니다).

## 가정한 자료 형식 (CSV 열 이름)
`일자, 점포코드, 상품코드, 상품명, 카테고리, 기초재고, 입고수량, 매입단가, 유통기한, 공급업체, 판매수량, 폐기수량, 반품수량, 판매단가, 행사, 기말재고, 적정재고, 품절시각`
- 계산에 쓰는 열: 일자, 상품코드, 상품명, 카테고리, 기초재고, 입고수량, 판매수량, 폐기수량, 기말재고, 행사(1/Y), 품절시각(0~23, 모르면 비움)
- 나머지(매입단가, 유통기한, 공급업체, 판매단가, 적정재고, 반품수량)는 읽기만 하고 아직 쓰지 않습니다.
- 날짜·상품코드가 없거나 수량이 음수인 줄은 건너뜁니다.

## 2026-11-03 보완 (검토 의견 반영)
- **완료된 주기만 판단**: 판매 종료(22시) 전의 오늘 기록은 판단에서 빼고 "판매 중"으로만 표시. 아침 실적과 최종 소진율을 섞지 않습니다.
- **비교 묶음 이름**: "행사 없이 판매를 마친 최근 5회", "행사 중 판매"를 따로 계산·표시(행사 중·행사 없는 기간의 관측 수·소진율·폐기율을 함께). "비행사"는 내부 용어 같아서 쓰지 않고, "평소"는 공휴일·장날을 뺀 것처럼 읽혀서 쓰지 않습니다.
- **정의 명시**: 일별 가용 재고 대비 합산 소진율. 입고 묶음별 추적은 아직 아님(이월이 있으면 안내). 재고 수량이 서로 안 맞는 줄은 제외하고 건수 표시. 분모 0은 계산 안 함.
- **배지는 짧게, 이유를 본문 첫 줄로**: 증량 검토 / 폐기 점검 / 행사 비교 / 참고(품절 시각이 없으면 "증량 검토" 대신 "품절 확인"). 행사 상품은 "행사 중에는 소진율 100%, 행사 없는 기간에는 82%였어요"처럼 사실만 보여 주고 행사 때문이라고 확정하지 않습니다.
- **홈 표시**: 상품마다 세 줄(확인할 이유 → 소진율·폐기율 → 다음 행동)만 보이고, 몇 회를 합산했는지·날짜별 수량·품절 시각·판정 기준은 "근거 보기" 안에. 확인할 상품은 최대 3개만 먼저 보이고 나머지(신호 없음·자료 부족·참고 포함)는 "다른 상품 보기"로 접음. 시연이면 "시연용 상품 데이터" 표시. 분류 표는 없앴습니다.
- **근거 보기는 짧게**: 합산 한 줄(예: 50/50 = 소진율 100%, 폐기 0개), 날짜별 한 줄씩(판매/팔 수 있던 · 폐기 · 품절 시각), 행사가 있으면 행사 중 한 줄, 그 상품의 신호에 해당하는 판정 기준 한 줄(검증 전 초기값)만 보입니다. 품절을 추정했거나 이월·재고 불일치가 있을 때만 그 한 줄이 더 붙습니다. 공식 설명(수식·평균과의 차이)은 [stats-guide.md](stats-guide.md) 6장에 있습니다.
- 아직 없음: "발주 변경 기록"(유지·증량·감량과 이유를 남기고 그 뒤 실제 판매·폐기를 돌아보는 기능). 저장 기능이 준비될 때 버튼을 붙입니다. 입고 묶음·소비기한 기준도 아직 없습니다.

## 규칙 한눈에
- 소진율 = 판매 ÷ (기초재고 + 입고), 폐기율 = 폐기 ÷ (기초재고 + 입고)
- 행사 날은 뺀 최근 평소 5번을 봅니다. 신호: 증량 검토 / 지금 수량이 맞을 가능성 / 감량·진열·구성 검토 / 행사 때만 소진 / 판단하지 않음
- 기준값은 PARAMS(stock.py)에 모여 있고 모두 **검증 전 초기값**입니다.
- 결과에는 판단에 쓴 날 수와 수량, 기준값, 품절을 시각으로 봤는지 추정으로 봤는지(stockout_basis)가 같이 들어갑니다.

## 가짜 자료로 확인한 것
- 심어 둔 신호 5가지 모두 40일 자료 5가지 난수에서 일치.
- 200일을 3일마다 판단하면: 증량 검토를 심은 상품 100%, 폐기 반복 100%, 행사 때만 85%, 잘 맞는 상품은 맞을 가능성 68% / 신호 없음 24% / **증량 검토로 잘못 9%**. 이 오탐 때문에 신호는 "한 번 살펴보라"는 용도입니다.
