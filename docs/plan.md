# SL 개발 계획 (Plan)

> [PRD.md](PRD.md)와 [spec.md](spec.md)를 **어떤 순서로 만들지** 정리한 문서입니다.
> 기술: 화면 **React**, 서버 **FastAPI**, 데이터 보관 **Supabase** (개발·시험 중에는 **SQLite**)

---

## 지켜야 할 약속

- Phase는 **순서대로** 진행하고, 각 Phase가 끝나면 "끝났다고 볼 기준"을 확인한 뒤 다음으로 넘어갑니다.
- 데이터 보관은 SQLite와 Supabase가 **똑같이 동작**해야 합니다. 개발은 SQLite로 하고, Supabase로 바꿔도 결과가 같은지 확인합니다.
- 비밀 값(비밀번호, API 키, Supabase 접속 정보)은 **`.env` 파일에만** 둡니다. 채팅과 문서에 적지 않고, 깃에 올리지 않습니다. (`.gitignore`에 이미 제외되어 있습니다)
- 화면과 서버는 분리합니다. (나중에 앱으로 확장하기 위해서입니다)

| **6. 설정 화면** | 방학 여러 기간 입력·수정·삭제, 비밀번호 바꾸기 | 저장한 값이 껐다 켜도 남아 있다 | 방학 날짜 입력해 보기 |

### Phase 순서의 이유

- 이상치 찾기(4)는 AI 없이도 쓸 수 있어서 AI 설명(5)과 분리했습니다.
- 예상 매출(7)은 방학 날짜가 필요해서 설정 화면(6) 뒤에 둡니다.
- Supabase 연결은 데이터를 처음 저장하는 Phase 2에서 확인합니다.

---

## Phase 1 상세

1. `frontend`에 React, `backend`에 FastAPI 빈 프로젝트를 만듭니다.
2. 서버에 "접속 가능한가"를 확인하는 기본 주소를 만듭니다.
3. 데이터 보관 연결을 만들고, 개발 중에는 SQLite를 씁니다. Supabase로 바꿀 수 있도록 설정 값 하나로 전환되게 합니다.
4. 비밀번호 확인, 5번 틀리면 10분 잠금, 30일 기억을 만듭니다.
5. 비밀번호 화면과 하단 메뉴(홈·파일 올리기·설정)가 있는 빈 화면 3개를 만듭니다.
6. `.env.example`을 만들어 필요한 설정 항목을 보여주고, 실제 값은 `.env`에 직접 넣게 합니다.
7. 확인 항목을 직접 해 보고 결과를 보고합니다.

### Phase 1 확인 항목 (spec 1번 기준)

- 비밀번호 없이 화면 주소를 열면 매출 숫자가 하나도 보이지 않는다.
- 비밀번호 없이 데이터 주소(서버)를 불러도 거절된다.
- 맞는 비밀번호로 들어가면 홈이 열린다.
- 틀린 비밀번호로는 홈이 열리지 않는다.
- 5번 연속 틀리면 잠시 막히고, 잠금이 풀린 뒤 들어가진다.
- 한 번 입력하면 30일 안에는 다시 묻지 않는다.
- 하단 메뉴 세 개가 각각의 화면을 연다.
