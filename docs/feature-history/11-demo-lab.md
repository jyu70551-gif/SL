## 1. 초안과 목적
- 점주의 실제 자료는 월·화·수 23일뿐이고 설 연휴 3일이 섞여 있다. 목~일은 본 적이 없다.
- 그래서 **분포를 흉내 낸 가짜 자료**로 화면과 코드의 동작을 확인한다. 가짜 자료에서 "경향을 발견"할 수는 없고 코드가 맞게 동작하는지만 확인할 수 있다(날씨 효과도 내가 정해서 심은 가정값).
- 정답이 표시된 이상(급증 2.5~4.5배, 급감 0.1~0.4배, 품절 0원)을 흩어 넣어 탐지 재현율·오경보를 측정한다([03-attention-detection.md](03-attention-detection.md)).

## 2. 문제와 수정
1. **시연 값이 실제 동작에 섞임**(장날) → 시연 DB가 장날을 미리 저장하지 않게 했다(2026-11-02).
2. **`start_demo.ps1 -Reset`이 콘솔 인코딩 때문에 멈춤** → 출력 인코딩 설정 수정(`4a267b0`).
3. **Vite 개발 서버가 옛 파일을 잡고 있는 경우가 있음** → 시연을 껐다 켜면 해결된다.
4. **시연 위치가 껐다 켤 때 바뀌는 것으로 보임**(이번 점검에서 확인, 원인은 아직 모름. [99-audit-2026-11-04.md](99-audit-2026-11-04.md)).

## 3. 안전 원칙
- 실제 매출 숫자는 저장소·문서·시험에 쓰지 않는다. 시험은 가상 숫자로만 한다.
- 가짜 데이터에는 항상 표시가 붙는다. 실제 수집 데이터와 섞이면 "실제·시연 데이터 섞임"으로 표시한다.
- 시연 데이터 공급 코드는 실제 수집 코드와 다른 파일에 있다.

## 4. 한계
- 가짜 자료는 선형으로 만들어져 선형 모형에 유리하다.
- 실제 매출 CSV가 `.sl-history/데이터_가져오기/csv`에 있어야 랩 데이터를 다시 만들 수 있다(`backend/lab/`은 git에 없고 도구로 다시 만들 수 있다).
