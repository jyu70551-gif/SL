# 랩 데이터 (시연·시험용 가짜 데이터)

> 실제 데이터가 월·화·수 23일뿐이라, **데이터가 많을 때 화면·탐지·AI가 어떻게 동작하는지** 보려고 만든 별도 DB와 도구입니다.
> **이 데이터로 어떤 경향도 "발견"할 수 없습니다.** 시연과 연습용입니다. 실제 Supabase에는 절대 쓰지 않습니다.

---

## 1. 무엇이 있나

| 파일 | 하는 일 |
|---|---|
| `backend/tools/make_lab_data.py` | 랩 DB(`backend/lab/lab.db`)와 정답 기록(`lab.truth.json`)을 만듭니다 |
| `backend/tools/eval_detection.py` | 정답이 표시된 이상을 탐지가 몇 개 잡는지, 오경보는 얼마나 되는지 셉니다 |
| `backend/tools/serve_lab.py` | 랩 DB로 서버를 켭니다 (화면 맨 위에 "시연용 데이터" 표시) |
| `backend/lab/` | 만들어진 DB들 (git에 올라가지 않음) |

## 2. 사용법 (backend 폴더에서)

```powershell
# 1) 랩 DB 만들기 (실제 매출 CSV가 .sl-history\데이터_가져오기\csv 에 있어야 함)
.\.venv\Scripts\python.exe tools\make_lab_data.py
#    --seed 숫자 : 같은 숫자면 같은 데이터   --start 2025-05-01 : 가짜로 채울 시작 날짜   --out lab\다른이름.db

# 2) 탐지 평가
.\.venv\Scripts\python.exe tools\eval_detection.py
#    시드를 바꿔 여러 번 만든 DB를 합쳐서 세면 더 믿을 수 있음:
#    --db lab\eval_seed1.db lab\eval_seed2.db lab\eval_seed3.db

# 3) 랩 서버 + 화면
.\.venv\Scripts\python.exe tools\serve_lab.py            # 포트 8100, 비밀번호는 .env 의 INITIAL_PASSWORD
#    다른 터미널:
cd ..\frontend
$env:VITE_PROXY_TARGET="http://127.0.0.1:8100"; npm.cmd run dev -- --port 5180
#    브라우저: http://localhost:5180
```

- 랩 서버는 `.env`의 **OpenAI 키를 그대로 씁니다.** AI 호출 기록과 월 한도는 랩 DB에 따로 쌓이지만, **OpenAI 요금은 같은 계정**에 붙습니다. 가짜 데이터와 실제 23일이 OpenAI로 전송됩니다.
- 실제 서버(8000)와 동시에 켤 수 있습니다. 랩 서버는 Supabase에 연결하지 않습니다.

## 3. 어떻게 만들어지나

1. **실제 날은 그대로 보존합니다.** 실제 23일은 원본 CSV와 완전히 같은 값으로 들어가고(파일 이름이 실제 CSV 이름), 빈 날짜만 가짜로 채웁니다(파일 이름 `synthetic`). 그래서 홈의 "오늘"은 실제 마지막 날 그대로입니다.
2. **가짜 날의 분포는 실제에서 추정합니다.**
   - 분류별로 팔린 날 비율, 팔린 날의 금액(로그 평균·표준편차), 단가
   - **하루 전체 공통 흔들림**은 가짜 총매출의 흔들림이 실제와 같아지도록 맞춥니다. (확인: 실제 평범한 날과 가짜 평범한 날의 총매출 로그 표준편차가 0.31 대 0.30)
   - 실제 휴일(설 연휴)은 평범한 날의 추정에서 뺍니다.
3. **실제 근거가 없는 것은 가정값입니다.** `make_lab_data.py` 맨 위의 `ASSUMED`와 `lab.truth.json`에 적혀 있습니다.
   - 목·금·토·일의 요일 효과 (월·화·수는 실제 값을 절반만 반영)
   - 장날(3·8·13·18·23·28일) +8%, 공휴일 −15%, 설·추석 연휴 −55% (대략의 달력, 정확한 공휴일표가 아님)
4. **정답이 표시된 이상**(급증 2.5~4.5배, 급감 0.1~0.4배, 품절 0원)을 흩어서 넣고 `lab.truth.json`에 기록합니다.
   - **평소와의 차이가 8,000원 이상인 의미 있는 크기만** 넣습니다. (탐지는 5,000원 미만 차이를 일부러 무시하므로, 작은 분류의 이상을 정답으로 넣으면 평가가 불공정해집니다)
   - 최근 일주일에도 몇 개를 넣어 홈에 점검 항목이 보이게 합니다. 실제 날에는 넣지 않습니다.
5. **점주가 남긴 것처럼 보이는 운영 상황 기록**(가짜)을 일주일보다 오래된 이상의 약 70%에 붙입니다. 일부는 "AI가 정리"로 표시됩니다. ("이전 기록" 기능 시험용)

## 4. 이 도구가 보여 준 것

랩 DB 5개(시드 1~5, 판단 가능한 정답 이상 177건)를 합쳐서 센 결과입니다. **가짜 데이터의 가정 아래에서의 결과**입니다.

### 4-1. 대분류 탐지 (현재 점수 3.0)
| | 정답을 잡은 비율 |
|---|---|
| 급증 | 82/99 (83%) |
| **급감** | **7/64 (11%)** |
| **품절(0원)** | **1/14 (7%)** |
| 전체 | 51% |
| 평범한 날 오경보 | 분류×날짜의 1.9%, 하루 평균 0.45건 |

**급감을 못 잡는 이유:** 현재 점수는 "금액 차이 ÷ 흩어진 정도"라서, 금액은 0 아래로 내려갈 수 없는데 흔들림이 큰 분류(예: 음료)에서는 0원이 돼도 점수가 −3에 못 미칠 수 있습니다. 급증은 위로 제한이 없어서 잘 잡힙니다.

### 4-2. 대안 실험: 급감은 비율(로그) 기준으로
| 방식 | 재현율 | 급증 | 급감 | 품절 | 오경보(하루) |
|---|---|---|---|---|---|
| 현재 (급증 3.0 / 급감 3.0) | 51% | 82/99 | 7/64 | 1/14 | 0.45건 |
| **혼합: 급증은 현재 3.0, 급감은 로그 2.5** | **73%** | 82/99 | **34/64** | **13/14** | 0.64건 |
| 혼합: 급감 로그 3.0 | 68% | 82/99 | 30/64 | 9/14 | 0.59건 |
| 혼합: 급증 2.5, 급감 로그 2.0 | 81% | 88/99 | 42/64 | 13/14 | 0.84건 |

- 대안은 **이 도구 안에서만 계산**했습니다. 앱의 탐지(`anomalies.py`)는 바꾸지 않았습니다. 반영하려면 계산을 바꾸는 일이므로 점주 승인이 필요합니다.
- 오경보 0.64건/하루는 대분류 24개 기준 약 1.5일에 한 번 정상인 변화가 올라온다는 뜻입니다. 점주가 [특이사항 없음]으로 닫는 비용과 놓치는 비용을 견줘서 정해야 합니다.

### 4-3. 총매출 통계 판단 (t 예측구간 검정)
평범한 날을 "탐지 기준 초과"로 잡은 비율이 이론상 5% 근처여야 하는데 **1.9%**였습니다. 보수적이라는 뜻입니다. 기록에 일부러 넣은 이상과 휴일이 섞여 표준편차가 커지고, 요일 효과가 분산에 섞이기 때문으로 보입니다. 오경보는 적지만 진짜 변화도 덜 잡을 수 있습니다.

### 4-4. 속도
`anomalies._analyze`는 날짜 수의 **제곱**에 비례해 느려집니다. 301일에 0.4초이고, 홈을 열 때마다 불립니다. 1,000일(약 3년)이면 4초 안팎으로 예상됩니다. 지금은 문제없지만 기록이 쌓이면 고쳐야 합니다. (같은 요일끼리 미리 묶어 두면 날짜 수에 비례하게 됩니다)

## 5. 한계 — 꼭 알아 두세요

- **가짜 데이터가 가정한 대로의 결과만 나옵니다.** 실제 분포가 더 치우쳤거나(연휴, 행사) 요일 효과가 크면 오경보와 재현율은 달라집니다.
- 실제 23일은 월·화·수뿐이고 표준편차 추정이 불안정합니다. 그 추정에서 만든 가짜 데이터는 같은 불확실성을 물려받습니다.
- 요일·장날·공휴일 효과를 **알아내는 데는 쓸 수 없습니다.** (알아낼 수 있는 최소 요일 차이는 현재 요일당 8번으로 약 2.2배, 1.5배를 보려면 요일당 약 32주가 필요)
- 시연 화면의 AI 문장은 가짜 데이터로 만든 것이므로 **실제 매장에 대한 이야기가 아닙니다.**
- **실제 DB와 섞지 마세요.** `backend/lab/`는 git에서 제외되어 있고, 서버는 랩 DB일 때만 "시연용 데이터" 표시를 띄웁니다.

## 6. 앞으로

- **목적 C(Phase 7 예측 모델 연습)용 데이터**는 아직 만들지 않았습니다. 효과 크기를 알고 넣은 가짜 데이터로 "예측 모델 코드가 효과를 되찾는지"를 확인하는 용도이며, Phase 7을 시작할 때 만듭니다.
