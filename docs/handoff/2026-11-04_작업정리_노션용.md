## 2. 하나씩 자세히

### 2-1. 통계 설명

- **요일효과를 빼는 이유:** 요일별로 따로 나누면 요일마다 표본이 1/7로 줄어 기준이 불안해집니다. 요일 차이를 한 번 빼고 전체를 한 줄로 보면 표본을 다 쓸 수 있습니다.
- **발생 CUSUM(1-8-1):** 평소 팔리던 상품이 연달아 안 팔리는지를 누적해서 보는 방법입니다. "4일 연속"이라는 문장은 평소 판매 확률이 0.8일 때만 맞고, 0.6이면 8일, 0.5면 약 10일입니다. calculation.md 11장에 표로 적었습니다.
- 계산 문서(`docs/calculation.md`)는 제목을 "계산 방식"으로 바꾸고 목차 표를 붙였습니다.

### 2-2. 가짜 데이터

- 오늘자 판매기록은 24줄짜리 CSV입니다. 변형 A는 담배를 크게 줄인 파일, 변형 B는 음료를 크게 늘린 파일입니다.
- 처음에는 절반 감소·2.5배로 만들었더니 알림이 뜨지 않아, 판정 점수를 직접 찾아 담배 −5.0점, 음료 +4.1점이 되는 값으로 정했습니다.
- 홈에서 −38.2%가 보이는데 "확인할 사항 없음"인 것은 홈 요약은 최근 4개 같은 요일의 **평균**, 알림은 **중앙값** 기준이라 생기는 차이입니다. (결정 대기)
- 빈 기간 채움은 기존 DB를 `demo.before_fill.db`로 백업한 뒤 진행했습니다.

### 2-3. 파일 올리기 화면

| 영역 | 바뀐 점 |
|---|---|
| 상단 | 파일 선택 → 내용 확인 → 업로드 → 반영 확인 4단계 표시 |
| 파일 선택 후 | 파일명, 파일 속 매출 날짜(읽을 수 있을 때만), "파일 빼기" |
| 집계 시각 | "같은 시각까지의 매출끼리 비교해요." 안내 |
| 업로드 버튼 | "파일을 먼저 골라 주세요" / "집계 시각을 골라 주세요" / "올리는 중…" 상태 구분 |
| 성공 | 같은 카드 안에 반영 날짜·집계 시각·올린 줄 수 |
| 덮어쓰기 | 교체했다는 사실과 운영 상황 기록이 지워진다는 안내 |
| 오류 | 원인과 다음 행동을 짧게 |
| 하단 | 최근 반영 날짜·집계 시각을 크게, 전체 일수·기간은 작게 |
| 달력 | 기록 있는 날(점)·선택한 날·오늘 구분과 범례, 날짜를 누르면 파일명·집계 시각 |

- 두 카드의 바깥 너비는 같습니다 (데스크톱 792px, 모바일 358px). 달력 칸 높이는 44px → 40px로 줄였습니다.
- 파일 속 날짜는 화면용 미리 보기이고, 요일 일치 같은 검사는 올릴 때 서버가 합니다.
- 새로 만든 파일: `frontend/src/salesFile.js`, `frontend/src/components/UploadCalendar.jsx`.
