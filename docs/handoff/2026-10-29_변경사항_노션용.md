## 2. 오늘 한 일 (시간순)

### 2-1. 디자인 (Phase 3 마무리)
- 글꼴 **Pretendard**(무료, 프로젝트에 포함)로 교체
- 앰버 `#F6B94A`를 주요 버튼·활성 메뉴·확인 필요 표시에만 사용
- 팔레트: 배경 `#0C1019`, 카드 `#151C2C`, 구분선 `#2A3346`, 핵심 글자 `#F3F5FA`, 설명 글자 `#B7C0D0`, 그래프·선택 `#969FFF`, 매출 증가 `#47D7AC`, 매출 감소 `#FF8A75`
- 장식용 그라데이션·그림자 제거, 선형 아이콘 통일, 키보드 포커스 표시
- 증감 색(민트·코랄)은 **홈 총매출 카드의 변화 방향에만** 사용. 정상·주의 표시와 다른 색

### 2-2. Phase 4 — 확인할 사항
- 대분류마다 **자기 자신의 평소**(이전의 같은 요일·같은 시각까지 기록 전부)와 비교해 크게 벗어난 날을 찾음
- 홈에 "오늘의 변화 / 이전 미확인 사항"으로 나눠 표시, 항목을 누르면 상세 그래프
- **운영 상황 기록**: 점주가 그날의 특이사항을 남김(행사·진열 변경 / 단체 구매 / 입고·품절 / 데이터 확인 필요 / 기타 / 모르겠어요 / 특이사항 없음 + 메모). 취소·수정 가능, 같은 날짜 파일을 덮어쓰면 초기화
- 용어 변경: "이상한 날" → **판매 변화가 큰 날**, "확인함·정상" → **운영 상황 기록**

### 2-3. 총매출 분석 (홈 매출 요약의 상세)
- 시간대까지 집계한 날짜별 총매출 시계열 그래프
- **통계 판단**: 쌓인 기록 전체(요일 구분 없음)의 분포에서 오늘 값이 어디인지 판단 — 로그 변환 후 **t 예측구간 검정**(유의수준 5%)
- 화면 3단계: ① 기본(오늘 매출·금액 차이·쉬운 한 줄 해석·그래프) → ② 비교 근거 펼치기 → ③ 분석 상세(수치·가정·검증 정보)
- 그래프 스타일: 판매선 1.5px, 기준선 1px 점선, 가로 그리드 분명, **화면 폭 그대로 그려 두께를 실제 CSS px로 적용**, 선택 날짜 라벨은 선·점과 겹치지 않는 자리로 자동 이동

### 2-4. 실제 데이터 넣기
- 점주의 `매출_초안.pdf`(23일치)를 날짜별 CSV로 변환해 Supabase에 저장 (마감 시각 오전 8시 기준)
- 변환 CSV와 스크립트는 `.sl-history/데이터_가져오기/`에 있음 (git 제외)

### 2-5. Phase 5 — AI 점검
- **5-1 연결 기반**: 키는 `backend/.env` 한 줄. **서버를 다시 켜지 않아도 반영.** 월 호출 한도(기본 300회), 연속 실패 시 10분 휴식, 키 확인 도구 `check_ai.py`
- **5-2 오늘의 점검**: 홈에서 우선순위 높은 변화 1~2개를 "숫자 근거 → 확인 질문 → 확인할 일"로 정리. 변화가 없거나 자료가 부족하면 AI를 부르지 않음. **키가 없어도 같은 모양의 고정 문구로 동작**
- **5-3 한마디 운영 메모**: "오늘 김밥 입고가 늦었어"처럼 쓰면 분류·날짜·운영 상황·시각으로 정리한 **초안**을 만들고, 점주가 확인해야만 저장
- **5-4 이전 기록과 평가**: 같은 분류에서 이전에 같은 방향의 변화가 있었을 때 점주가 남긴 기록을 보여줌(단정하지 않음), "도움이 됐어요" 평가, 설정 화면 AI 상태 카드
- AI는 **원인을 단정하지 않음**. 가드가 없는 숫자·분류, 단정 표현(때문·원인은·확실), 판정 표현(정상·문제없음), 링크, 키 모양 문자열을 막음. 막히면 한 번 다시 시키고 그래도 안 되면 고정 문구
- 실제 키로 확인: 모델은 키로 쓸 수 있는 것 중 **자동 선택**(확인 당시 `gpt-5.4-mini`), 점검 생성 성공, 이번 달 5회 사용
- **한마디 운영 메모는 실제 모델로 아직 시험하지 못했음** (화면에서 써 보고 확인 필요)

- [ ] 같은 Supabase를 쓰면 데이터가 그대로 보입니다. 다른 DB를 쓰면 빈 상태로 시작합니다.

### 5-3. 서버(backend) 준비
Windows PowerShell 기준입니다. (macOS/Linux는 아래 표 참고)

```powershell
cd SL\backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
```

| 환경 | 가상환경 파이썬 | 복사 |
|---|---|---|
| Windows | `.\.venv\Scripts\python.exe` | `copy .env.example .env` |

### 5-4. `.env` 항목 (값은 직접 채움)
| 항목 | 설명 |
|---|---|
| `INITIAL_PASSWORD` | SL 사용 비밀번호(8글자 이상). **DB가 비어 있을 때 처음 한 번만** 쓰임 |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_SSLMODE` | Supabase **Session pooler** 값 (Connect 버튼 → Session pooler). `DB_USER`는 `postgres.프로젝트ID` 형태 |
| `FRONTEND_ORIGINS` | 화면 주소. 기본 `http://localhost:5173` |
| `OPENAI_API_KEY` | AI 점검을 켜는 **유일한 필수 항목**. 비워 두면 고정 문구로 동작 |
| `AI_ENABLED`, `OPENAI_MODEL`, `AI_MONTHLY_CALL_LIMIT`, `AI_TIMEOUT_SECONDS`, `AI_MAX_RETRIES` | 선택. 비우면 기본값 (모델은 자동 선택, 월 300회) |

### 5-5. 확인하고 실행
```powershell

.\.venv\Scripts\python.exe check_db.py        # DB 연결 확인 (데이터는 바꾸지 않음)

.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --port 8000
```

## 8. 문제 해결 메모

| 증상 | 원인·해결 |
|---|---|
| PowerShell에서 `npm`이 실행되지 않음 | 실행 정책 때문. `npm.cmd`로 실행 |
| 서버가 "포트 8000 사용 중" | 이미 서버가 켜져 있음. 끌 때는 **해당 PID만** `taskkill /T /F /PID 번호` (python.exe 전체를 끄지 말 것) |
| `localhost`로 서버가 안 열림 | IPv6로 연결될 수 있음. `127.0.0.1` 사용 |
| 서버가 "필요한 테이블이나 열이 아직 없어요"로 멈춤 | `alembic upgrade head` 실행 |
| DB 연결이 10초 걸리고 실패 | `DB_HOST`가 Session pooler 주소인지, `DB_USER`가 `postgres.프로젝트ID`인지, `DB_PASSWORD`가 **데이터베이스 비밀번호**인지 확인 (`check_db.py`가 안내) |
| alembic이 한글 때문에 오류 | `alembic.ini`는 ASCII만 써야 함 (Windows 기본 인코딩) |
| AI 설정 화면이 "키가 아직 없어요" | `backend/.env`에 `OPENAI_API_KEY=` 한 줄 확인. 오타 시 `check_ai.py`가 이유를 알려 줌 |
| 점검이 "AI 설명 없이 계산 결과로" 라고 나옴 | 월 한도 도달, 연결 불안정(10분 휴식), 키 오류 중 하나. 설정 화면에서 상태 확인 |
| 로그인 5번 실패 잠금 | 10분 기다리거나 `set_password.py`로 비밀번호 재설정(잠금·로그인 기록 초기화) |
