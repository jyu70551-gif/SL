# SL 동작 설명서 (Spec)

> [PRD.md](PRD.md)에서 정한 기능이 **실제로 어떻게 움직여야 하는지**를 사용자의 행동과 결과 중심으로 적은 문서입니다.
> PRD에 없는 기능은 넣지 않았습니다.
> PRD만으로 정할 수 없었던 내용은 점주에게 하나씩 확인해 반영했습니다. (맨 아래 "확인 필요 목록" 참고)

## 0. 먼저 알아 둘 약속

### 0-1. 누가 쓰나요?

- 사용하는 사람은 **점주 한 명**뿐입니다. 회원가입도, 여러 계정도, 권한 구분도 없습니다.
- 비밀번호를 통과하면 **모든 화면을 보고, 올리고, 바꿀 수 있습니다.**
- 비밀번호를 모르는 사람은 아무것도 볼 수 없습니다.

### 0-2. 모든 카드에 공통으로 보이는 것

- 매출을 보여주는 모든 카드에는 **"몇 시까지의 매출인지"** 가 함께 표시됩니다. (파일을 올릴 때 입력한 시각입니다)

### 0-3. 일이 잘못됐을 때의 기본 원칙

PRD에는 실패했을 때의 동작이 적혀 있지 않아서, 다음을 **기본 원칙**으로 정했습니다. (점주 확인 완료)

- 실패하면 **이미 저장된 데이터는 그대로 두고**, 화면에 **무엇이 문제인지 쉬운 말로** 알려줍니다.
- 잘못된 내용이 일부만 저장되는 일은 없습니다. (전부 저장되거나, 전혀 저장되지 않거나)

### 0-4. "오늘"과 "내일"이 뜻하는 날

PRD는 "오늘 총매출", "내일 예상 매출"이라고만 적었습니다. 점주 확인으로 다음과 같이 정했습니다.

- **오늘 = 올려 둔 파일 중 가장 최근 날짜**입니다. 어제 파일까지만 올렸다면 어제가 "오늘"로 보입니다. (그래서 파일을 늦게 올려도 화면이 비지 않습니다)
- **내일 = 오늘의 다음 날**입니다.
- 이미 쌓인 예전 날짜 파일을 고쳐 올려도(덮어쓰기) "오늘"은 바뀌지 않습니다.

### 0-5. 데이터는 어디에 저장되나요?

- 이 문서에서 "저장된다"고 쓴 모든 것은 **Supabase**(인터넷 데이터 보관함)에 저장됩니다. 개발·시험 중에는 내 컴퓨터의 **SQLite**에 저장합니다.
- 두 곳에서 **동작이 똑같아야 합니다.** (같은 파일을 올리면 같은 결과가 나와야 합니다)
- **확인 방법:** 같은 CSV와 같은 순서의 조작을 SQLite와 Supabase에서 각각 해 보고, 홈 카드 숫자와 확인 필요 목록이 같은지 봅니다.

### 0-6. 올린 데이터는 지울 수 있나요?

- PRD에는 올린 데이터를 **지우는 기능이 없습니다.** 첫 버전에서도 만들지 않습니다.
- 데이터를 바꾸는 방법은 **같은 날짜의 파일을 다시 올려 덮어쓰는 것** 하나뿐입니다.

## 1. 비밀번호로 들어가기 (화면 D)

| 항목 | 내용 |
|---|---|
| 관련 PRD | 1번 사용자 표(접근 제한), 화면 D, 완성 기준 |

### 1) 사용자가 하는 일
- 인터넷 주소를 열면 **비밀번호 입력 화면**이 나옵니다.
- 비밀번호 하나를 입력하고 들어가기를 누릅니다.
- 입력 항목은 **비밀번호 하나**뿐입니다. (아이디 없음)

### 2) 정상일 때
- 비밀번호가 맞으면 **초기 화면(홈)** 이 열립니다.
- 저장되는 것: 없습니다.
- 비밀번호 입력 화면은 **서비스에 처음 들어올 때**(또는 30일이 지났을 때) 나옵니다. 한 번 입력하면 그 폰에서 30일 동안은 다시 묻지 않습니다.

### 3) 실패했을 때
- 비밀번호가 틀리면 화면이 열리지 않고 **"비밀번호가 맞지 않습니다"** 같은 안내가 나옵니다.
- 비밀번호 없이 다른 화면의 주소를 직접 열어도 **비밀번호 화면으로 돌아갑니다.**
- 비밀번호는 **점주가 정해 두고**, 바꾸고 싶으면 **설정 화면에서 바꿉니다.** (7번 참고, 점주 확인 완료. PRD의 설정 화면에 새로 더해진 항목입니다)
- **연속으로 5번 틀리면** 일정 시간(예: 10분) 동안 비밀번호를 입력할 수 없고, 그 사이에는 **"잠시 후 다시 시도해 주세요"** 안내가 나옵니다. (점주 확인 완료. 잠그는 시간은 10분을 기준으로 적었습니다)
- 올바른 비밀번호를 입력하면 틀린 횟수는 처음부터 다시 셉니다.
- 비밀번호를 한 번 입력하면 **그 폰(브라우저)에서 30일 동안 기억**합니다. 30일이 지나면 다시 입력합니다. (점주 확인 완료)

### 4) 누가 볼 수 있나요?
- 비밀번호를 아는 사람은 누구나 같은 권한으로 쓸 수 있습니다. 비밀번호 화면 자체는 누구에게나 보입니다.

### 5) 제대로 만들었는지 확인하는 방법
- 비밀번호 없이 주소를 열면 **매출 숫자가 하나도 보이지 않는지** 확인합니다.
- 맞는 비밀번호로 들어가면 홈이 열립니다. 폰을 닫았다 다시 열어도 30일 안에는 비밀번호를 다시 묻지 않는지 봅니다.
- 틀린 비밀번호로는 홈이 열리지 않습니다.
- 연속으로 5번 틀리면 잠시 막히고, 잠금이 풀린 뒤 맞는 비밀번호로 들어가지는지 봅니다.
- 휴대폰과 PC에서 각각 인터넷 주소로 접속되는지 확인합니다.

## 2. 기능 1 — 매출 파일 올리기 (화면 C)

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 1, 화면 C, 완성 기준 |

### 입력 항목과 조건

| 입력 | 조건 (PRD 기준) |
|---|---|
| **CSV 파일 1개** | 열이 **상품코드, 대분류, 판매수량, 판매액, 연도, 달, 일, 요일** 8개입니다. **파일 하나에는 하루치만** 들어 있어야 합니다. (점주 확인 완료) |
| **"몇 시까지의 매출인지" 시각** | 올릴 때 **한 번 직접 입력**합니다. 그 시각이 파일의 날짜에 붙습니다. **시(時)만 선택**합니다. (예: 오후 10시, 분은 입력하지 않음) (점주 확인 완료) |
| **덮어쓰기 확인** | 같은 날짜가 이미 있을 때만 나오는 확인 창에서 "덮어쓰기" 또는 "취소"를 누릅니다. |

여러 날짜가 섞인 파일은 올릴 수 없습니다. (아래 3) 실패했을 때 참고)

### 1) 사용자가 하는 일
1. 하단 메뉴에서 **파일 올리기**를 누릅니다.
2. CSV 파일을 고릅니다.
3. 몇 시까지의 매출인지 시각을 입력합니다.
4. 올리기를 누릅니다.
5. 같은 날짜가 이미 있으면 **확인 창**이 뜹니다. 덮어쓸지 취소할지 고릅니다.

### 2) 정상일 때
- **저장되는 것:** 파일 안의 날짜별 매출(대분류별 판매수량·판매액), 그리고 입력한 시각입니다. 이전에 올린 데이터는 **지워지지 않고 계속 쌓입니다.**
- **같은 날짜를 덮어쓰면:** 그 날짜의 데이터가 새 파일 내용으로 바뀝니다. 다른 날짜는 그대로입니다.
- **화면에 보이는 것:** 올리기가 끝났다는 안내가 나옵니다. 그 후 홈의 카드들이 새 데이터로 **1분 안에** 채워집니다.
- 데이터가 아직 적으면 일부 카드는 "데이터가 더 필요해요" 상태일 수 있습니다. (6번 참고)

### 3) 실패했을 때
- 아래 경우는 **잘못된 파일**로 보고 **저장하지 않고 이유를 알려줍니다.** (0-3의 기본 원칙, 점주 확인 완료)
  - 열 이름이 PRD의 8개(상품코드, 대분류, 판매수량, 판매액, 연도, 달, 일, 요일)와 다름
  - 판매수량·판매액이 숫자가 아니거나 비어 있음
  - 연도·달·일이 존재하지 않는 날짜이거나, 파일 안에 **여러 날짜가 섞여** 있음
  - **요일이 날짜와 맞지 않음** (예: 2026년 2월 25일인데 요일이 "월")
- 위 네 가지에 해당하지 않는 문제(예: 대분류가 24개보다 적음)는 막지 않고 저장합니다.
- 시각을 입력하지 않았거나 올바르지 않으면 **올려지지 않고** 시각을 다시 입력하라고 안내합니다.
- 덮어쓰기 확인 창에서 **취소**하면 아무것도 바뀌지 않습니다. 기존 데이터가 그대로 남습니다.
- 파일에 **"합계" 줄**(상품코드 칸이 "-"로 표시되는 줄)이 있어도 **저장하지 않습니다.** 총매출과 총 판매수량은 대분류 숫자를 더해서 직접 계산합니다. 합계 줄이 없는 파일도 올릴 수 있습니다. (점주 확인 완료)
- 덮어쓰기를 하면 그 날짜에 눌러 둔 **"확인함·정상" 기록은 모두 지워지고**, 새 숫자로 이상 여부를 **다시 판단**합니다. 이상하면 다시 "확인이 필요한 대분류"에 올라옵니다. (점주 확인 완료)
- 덮어쓰기 확인 창에는 이 사실(확인 기록이 지워짐)을 **함께 알려줍니다.**

### 4) 누가 볼 수 있나요? 누가 바꾸거나 지울 수 있나요?
- 점주만 올릴 수 있습니다.
- **바꾸기:** 같은 날짜 파일을 다시 올려 덮어쓰기. **지우기:** 없음 (0-6 참고).

### 5) 제대로 만들었는지 확인하는 방법
- 사용 가능한 정상 CSV(8개 열)를 올리면 **1분 안에** 홈이 갱신되는지 봅니다.
- 다음 날 파일을 올리면 **전날 데이터가 사라지지 않고 쌓여** 있는지 봅니다.
- 같은 날짜를 다시 올렸을 때 **확인 창이 뜨는지**, "취소"하면 변화가 없는지, "덮어쓰기"하면 새 값으로 바뀌는지 봅니다.
- 그 날짜에 "확인함·정상"을 눌러 둔 항목이 있었다면, 덮어쓴 뒤 **확인 기록이 지워지고 이상 여부가 다시 판단되는지** 봅니다. (확인 창에도 그 안내가 있는지)
- 시각을 입력하지 않으면 올려지지 않는지 봅니다.
- 열이 빠진 파일, 숫자가 아닌 판매액이 있는 파일, 여러 날짜가 섞인 파일, 요일이 날짜와 맞지 않는 파일을 각각 올려 **저장되지 않고 이유가 보이는지** 봅니다.
- 홈의 모든 카드에 방금 입력한 시각이 표시되는지 봅니다.

### 구현하면서 정한 세부 사항 (Phase 2)

PRD·spec에 직접 적혀 있지 않아 개발하면서 정한 내용입니다. 다르게 하고 싶으면 알려 주세요.

- **파일 형태:** 쉼표·탭·세미콜론으로 나뉜 CSV를 읽습니다. 글자는 UTF-8과 한글 엑셀(CP949) 모두 읽습니다. 파일 크기는 **2MB 이하**입니다.
- **열 순서:** 열 이름만 맞으면 순서는 달라도 됩니다.
- **숫자:** 판매수량·판매액은 **정수**만 받습니다. `1,234`처럼 천 단위 쉼표는 허용하고, 소수(`1.5`)는 숫자가 아닌 값으로 거절합니다.
- **요일:** `수`와 `수요일` 두 가지 표기를 모두 받습니다.
- **시각:** **오전 12시(자정, 0시)부터 오후 11시까지 24개** 중에서 고릅니다. (자정 이후에 마감하는 경우의 표현은 아직 따로 두지 않았습니다.)
- **오류 안내:** 문제가 있는 줄 번호와 이유를 보여주고, 많으면 10건까지만 보여준 뒤 "…외 N건"으로 알려줍니다.
- **올려 둔 날짜 목록:** 올린 데이터가 쌓이는 것을 볼 수 있도록 파일 올리기 화면 아래에 올려 둔 날짜(최신순)와 시각을 보여줍니다. 보기만 하고 지우거나 바꾸는 기능은 없습니다.
- **덮어쓰기 확인 창:** 이미 저장된 시각과 "확인함·정상 기록이 지워진다"는 안내를 함께 보여줍니다. ("확인함·정상" 기록 자체는 Phase 4에서 만들고, 그때 덮어쓰기와 연결합니다)

## 3. 기능 2 — 확인이 필요한 대분류 (화면 A 첫 카드, 화면 B)

기능 2는 네 가지 동작으로 나누어 적었습니다.

### 3-1. 확인이 필요한 대분류 목록과 AI 설명 (홈의 첫 카드)

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 2, 화면 A 카드 1 |

#### 1) 사용자가 하는 일
- 홈을 엽니다. 별도로 입력하거나 누를 것은 없습니다. 목록이 자동으로 보입니다.

#### 2) 정상일 때
- **보이는 것:** 평소와 크게 다른 대분류가 목록으로 올라옵니다. 항목마다 대분류 이름과 **AI 설명**이 있습니다.
- **AI 설명의 모양:** **숫자 근거를 먼저** 말하고, 원인은 **"~일 수 있습니다"라는 가능성**으로만 말합니다. 단정하지 않습니다.
  - 예: "담배가 같은 요일 평소의 3배입니다. 대량 구매 또는 입력 오류일 수 있습니다."
- **어떻게 고르나:** 같은 요일끼리 비교해서 크게 벗어난 대분류를 **통계**가 고릅니다. AI는 고르는 일이 아니라 **설명**만 합니다.
- **저장되는 것:** 어떤 대분류가 어떤 날 이상으로 판단되었는지와 AI 설명. (저장하는 표의 모양은 설계 단계에서 정합니다)
- 이상한 대분류가 없으면 **"확인이 필요한 항목이 없습니다"** 라는 안내가 보입니다.
- 거의 늘 0인 대분류는 **따로 처리**됩니다. 구체적인 계산법과 기준은 설계 단계에서 확정합니다. (PRD 미정 7번)
- 데이터가 적은 동안은 이 카드가 **"데이터가 더 필요해요"** 안내와 진행 상황을 보여줍니다. 몇 일 치부터 보여줄지는 설계 단계에서 확정합니다. (PRD 미정 7번)

#### 3) 실패했을 때
- 통계는 계산됐지만 **AI 설명을 받아오지 못한 경우**: 항목은 **목록에 그대로 보여주고**, 설명 자리에 **"설명을 불러오지 못했어요"** 와 통계가 계산한 **숫자 근거**(예: 같은 요일 평소의 3배)만 보여줍니다. 중요한 경고가 사라지지 않습니다. (점주 확인 완료)
- 이 상태에서도 그래프 보기와 "확인함·정상" 누르기는 그대로 할 수 있습니다.
- 데이터가 부족할 때는 위의 "데이터가 더 필요해요" 안내가 나옵니다. 오류가 아니라 정상 상태입니다.

#### 4) 누가 볼 수 있나요?
- 점주만 볼 수 있습니다. 이 목록은 시스템이 만들며, 점주가 직접 고치거나 지울 수 없습니다. 점주가 할 수 있는 일은 3-3의 "확인함·정상"입니다.

#### 5) 제대로 만들었는지 확인하는 방법
- 일부러 한 대분류를 평소보다 훨씬 크거나 작게 만든 파일을 올려, **그 항목이 목록에 올라오는지** 봅니다.
- 올라온 항목마다 설명이 있고, **숫자 근거가 먼저, 원인은 가능성 표현**으로 되어 있는지 봅니다.
- AI 연결이 안 되는 상태에서 파일을 올렸을 때, 항목은 목록에 보이고 설명 자리에 **"설명을 불러오지 못했어요"와 숫자 근거**가 나오는지 봅니다.
- 평소와 비슷한 데이터만 올렸을 때 **목록이 비어 있고 안내가 나오는지** 봅니다.
- 데이터를 처음 몇 개만 올렸을 때 **"데이터가 더 필요해요"** 가 보이는지 봅니다.

### 3-2. 대분류 그래프 (화면 B)

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 2, 화면 B |

#### 1) 사용자가 하는 일
- 홈의 "확인이 필요한 대분류" 항목 **하나를 누릅니다.**

#### 2) 정상일 때
- **새 화면**이 열립니다.
- **보이는 것:** 그 대분류의 **날짜별 매출 그래프**와, 그래프 위에 **이상한 날 표시**입니다.
- 저장되는 것: 없습니다. (이미 쌓인 데이터를 보여주기만 합니다)
- 그래프에 그리는 값은 **판매액(매출 금액)** 입니다. (점주 확인 완료)

#### 3) 실패했을 때
- 그래프에 쓸 데이터가 없거나 너무 적으면 **"데이터가 더 필요해요"** 안내를 보여줍니다.

#### 4) 누가 볼 수 있나요?
- 점주만 볼 수 있습니다. 그래프는 보는 화면이라 고치거나 지울 수 없습니다.

#### 5) 제대로 만들었는지 확인하는 방법
- 목록의 항목을 누르면 새 화면이 열리고, 그래프에서 **이상한 날이 표시되어 있는지** 봅니다.
- 이상한 날이 목록에 올라온 날짜와 일치하는지 봅니다.

### 3-3. "확인함·정상"으로 답하기

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 2 마지막 항목, 화면 B, 완성 기준 |

#### 1) 사용자가 하는 일
- 목록의 항목(또는 그 항목의 그래프 화면)에서 **"확인함·정상"** 을 누릅니다. 입력할 글자는 없습니다.

#### 2) 정상일 때
- **보이는 것:** 누른 항목이 **홈의 목록에서 사라집니다.**
- **저장되는 것:** 점주가 그 항목을 확인했다는 기록입니다.
- 사라진 항목은 **다시 경고로 뜨지 않습니다.**
- "다시 뜨지 않는다"의 범위는 **그 대분류의 그 날짜 하나**입니다. (예: 2월 17일 담배를 확인함으로 누르면 그 날만 사라집니다. 다른 날짜에 담배가 또 이상하면 새로 경고가 뜹니다) (점주 확인 완료)

#### 3) 실패했을 때
- 누르는 데 실패하면(기록이 저장되지 않으면) 항목은 **목록에 그대로 남고** 실패했다는 안내가 나옵니다. 사라진 것처럼 보이는데 사실은 저장이 안 된 상태가 되면 안 됩니다. (0-3의 기본 원칙)

#### 4) 누가 볼 수 있나요? 누가 바꾸거나 지울 수 있나요?
- 점주만 누를 수 있습니다. **취소**는 3-4에서 할 수 있습니다.

#### 5) 제대로 만들었는지 확인하는 방법
- "확인함·정상"을 누르면 항목이 목록에서 사라지는지 봅니다.
- 같은 데이터를 다시 열거나 다른 날짜의 새 파일을 올려도 **그 날짜의 그 대분류는 다시 경고로 뜨지 않는지** 봅니다.
- 같은 대분류의 **다른 날짜**가 이상할 때는 **새로 경고가 뜨는지** 봅니다.
- 서비스를 껐다 켜도 기록이 남아 있는지 봅니다.

### 3-4. "확인한 항목" 보기와 취소

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 2 마지막 항목, 화면 B, 6번 |

#### 1) 사용자가 하는 일
- 홈의 "확인이 필요한 대분류" 카드 안의 **"확인한 항목" 링크**를 누릅니다. (하단 메뉴는 늘리지 않습니다)
- 거기서 다시 경고로 되돌리고 싶은 항목의 **취소**를 누릅니다.

#### 2) 정상일 때
- **보이는 것:** "확인함·정상"으로 처리한 항목들이 모아서 보입니다.
- 취소하면 그 항목은 **다시 홈의 확인 필요 목록에 나타납니다.**
- **저장되는 것:** 확인 기록이 지워집니다.
- 목록에 항목이 없으면 "확인한 항목이 없습니다" 안내가 나옵니다.

#### 3) 실패했을 때
- 취소에 실패하면 항목은 **"확인한 항목"에 그대로 남고** 실패 안내가 나옵니다. (0-3의 기본 원칙)

#### 4) 누가 볼 수 있나요?
- 점주만 볼 수 있고 취소할 수 있습니다.

#### 5) 제대로 만들었는지 확인하는 방법
- 확인한 항목이 "확인한 항목" 링크에서 모두 보이는지 봅니다.
- 취소하면 홈의 목록에 **다시 올라오는지** 봅니다.
- 홈의 카드 안에서 링크로 들어가고, **하단 메뉴가 세 개 그대로**인지 봅니다.

## 4. 기능 3 — 오늘 총매출·판매수량 (홈 카드 2)

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 3, 화면 A 카드 2 |

### 1) 사용자가 하는 일
- 홈을 엽니다. **입력하거나 누를 것은 없습니다.**

### 2) 정상일 때
- **보이는 것:**
  - 오늘의 **총매출**(판매액 합계)과 **총 판매수량**
  - **같은 요일과 비교한 결과**
  - **몇 시까지의 매출인지**
- **저장되는 것:** 없습니다. (기능 1에서 저장한 데이터를 계산해서 보여줍니다)
- **같은 요일과의 비교**는 **지난 여러 주 같은 요일의 평균**과 비교합니다. (예: "평소 수요일보다 +12%") 몇 주를 평균 낼지, 몇 주 치가 쌓여야 보여줄지는 설계 단계에서 확정합니다. (PRD 미정 7번) (점주 확인 완료)
- 총매출과 총 판매수량은 파일의 "합계" 줄을 쓰지 않고 **대분류 숫자를 더해서** 구합니다. (점주 확인 완료)

### 3) 실패했을 때
- 아직 올린 파일이 하나도 없으면 **"파일을 올려 주세요"** 같은 안내가 나옵니다.
- 같은 요일 데이터가 아직 부족하면 비교 부분만 **"데이터가 더 필요해요"** 안내가 나옵니다. 오늘 총매출과 총 판매수량은 그대로 보입니다. (PRD의 "비교 카드는 데이터가 쌓일 때까지 안내" 규칙에 따름)

### 4) 누가 볼 수 있나요?
- 점주만 볼 수 있습니다. 이 카드는 보는 화면이라 고치거나 지울 수 없습니다. 숫자를 바꾸려면 기능 1의 덮어쓰기를 합니다.

### 5) 제대로 만들었는지 확인하는 방법
- 파일 하나를 올린 뒤, 카드의 총매출·총 판매수량이 **파일의 숫자를 직접 더한 값과 같은지** 계산기로 확인합니다.
- 같은 요일 데이터가 충분히 쌓였을 때 비교 결과가 보이는지, 적을 때는 안내가 나오는지 봅니다.
- 카드에 입력한 시각이 표시되는지 봅니다.

## 5. 기능 4 — 즉석식품 요약 (홈 카드 3)

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 4, 화면 A 카드 3 |

### 1) 사용자가 하는 일
- 홈을 엽니다. **입력하거나 누를 것은 없습니다.**

### 2) 정상일 때
- **보이는 것:**
  - **간편식사**와 **즉석조리** 두 대분류의 오늘 판매량
  - **평소 범위와 비교**해서 많은지 적은지
  - **몇 시까지의 매출인지**
- 상품 하나하나(예: 삼각김밥, 햄버거)가 아니라 **대분류 단위**입니다.
- **저장되는 것:** 없습니다. (계산해서 보여줍니다)
- "평소 범위"를 어떻게 정하는지(몇 주를 보고 어떤 폭으로 잡는지)는 PRD에 없고 설계 단계에서 확정합니다. (PRD 미정 7번)
- 보여주는 값은 **판매수량(개수)** 입니다. (점주 확인 완료)

### 3) 실패했을 때
- 아직 올린 파일이 없으면 **"파일을 올려 주세요"** 안내가 나옵니다.
- 평소 범위를 만들 데이터가 부족하면 비교 부분만 **"데이터가 더 필요해요"** 안내가 나옵니다. 오늘 판매량은 그대로 보입니다.

### 4) 누가 볼 수 있나요?
- 점주만 볼 수 있습니다. 보는 화면이라 고치거나 지울 수 없습니다.

### 5) 제대로 만들었는지 확인하는 방법
- 오늘 파일의 간편식사·즉석조리 판매수량과 카드 숫자가 **같은지** 봅니다.
- 평소보다 훨씬 많은 값을 올렸을 때 "많음"으로, 훨씬 적은 값을 올렸을 때 "적음"으로 표시되는지 봅니다.
- 데이터가 적을 때 안내가 나오는지 봅니다.
- 카드에 시각이 표시되는지 봅니다.

## 6. 기능 5 — 내일 예상 매출 (홈 카드 4)

| 항목 | 내용 |
|---|---|
| 관련 PRD | 기능 5, 화면 A 카드 4 |

### 1) 사용자가 하는 일
- 홈을 엽니다. **입력하거나 누를 것은 없습니다.**
- 방학 날짜는 화면 E(7번)에서 미리 입력해 두면 예상에 반영됩니다.

### 2) 정상일 때
- **보이는 것:** 내일 매출의 **예상 범위와 가운데 값**입니다. (예: "약 12만 원, 범위 10~14만 원") **"참고용"** 표시가 반드시 함께 보입니다.
- **계산에 쓰는 요소 (PRD 그대로):**

| 요소 | 어디서 오나요? |
|---|---|
| 요일 | 날짜에서 계산 |
| 장날 | 5일장, **3, 8, 13, 18, 23, 28일** |
| 날씨 | **기상청 공공 데이터** (시흥시 기준) |
| 방학 여부 | **점주가 직접 입력한 날짜** |
| 명절·공휴일 | **공공 데이터** |

- 계산에는 **회귀모형**을 씁니다. 구체적인 모형과 범위의 폭은 설계 단계에서 확정합니다.
- **저장되는 것:** 예상 결과(필요하면)는 설계 단계에서 정합니다. PRD에서 저장하기로 한 것은 없습니다.
- 데이터가 적어서 예상이 자리를 잡지 못한 동안에는 **"데이터가 더 필요해요"** 안내와 진행 상황이 보입니다. 몇 일 치부터 보여줄지는 설계 단계에서 확정합니다. (PRD 미정 7번)

### 3) 실패했을 때
- 날씨나 공휴일 정보를 가져오지 못했을 때: **가져온 정보만으로 예상**을 계산하고, 카드에 **빠진 정보가 있다고 표시**합니다. (예: "날씨 정보를 불러오지 못해 날씨는 반영하지 않았어요") 예상 카드가 통째로 사라지지는 않습니다. (점주 확인 완료)
- 데이터 부족은 오류가 아니라 위의 안내 상태입니다.

### 4) 누가 볼 수 있나요?
- 점주만 볼 수 있습니다. 보는 화면이라 고치거나 지울 수 없습니다.

### 5) 제대로 만들었는지 확인하는 방법
- 카드에 **범위와 가운데 값**이 같이 나오고, **"참고용"** 표시가 있는지 봅니다.
- 가운데 값이 범위 안에 있는지 봅니다.
- 내일이 **장날(3, 8, 13, 18, 23, 28일)** 이거나 **공휴일·명절**일 때, 같은 조건이 아닌 날과 **예상이 달라지는지** 봅니다.
- 방학 날짜를 입력하고 나서 그 기간의 예상이 반영되는지 봅니다.
- 날씨 정보를 불러올 수 없는 상태에서 예상이 **그대로 나오고, "날씨는 반영하지 않았어요" 같은 표시가 있는지** 봅니다.
- 데이터가 적을 때 안내가 나오는지 봅니다.
- 카드에 시각이 표시되는지 봅니다.

- **여러 기간**을 입력할 수 있습니다. (예: 여름 방학, 겨울 방학) 입력한 기간은 **목록**으로 보이고, **각 기간을 수정하거나 삭제**할 수 있습니다. (점주 확인 완료)
- 과거 날짜와 미래 날짜 모두 입력할 수 있습니다. (PRD에 날짜 제한이 없습니다)
- **서로 겹치는 기간**을 입력해도 **저장**됩니다. 목록에는 입력한 그대로 남고, 예상 매출을 계산할 때는 **겹치는 기간을 같은 방학으로 합쳐서** 처리합니다. (점주 확인 완료)

#### 1) 사용자가 하는 일
1. 하단 메뉴에서 **설정**을 누릅니다.
2. 방학 **시작 날짜**와 **끝 날짜**를 입력합니다.
3. 저장합니다. 방학 목록에 새 기간이 추가됩니다.
4. 이미 입력한 기간을 고치려면 목록에서 그 기간의 **수정**을, 없애려면 **삭제**를 누릅니다.

#### 2) 정상일 때
- **저장되는 것:** 방학 시작·끝 날짜입니다. 수정하면 그 기간의 날짜가 바뀌고, 삭제하면 그 기간이 없어집니다.
- **화면에 보이는 것:** 저장했다는 안내와 입력한 방학 **목록**입니다.
- 이후 **내일 예상 매출**(6번)에서 그 기간을 방학으로 계산합니다.

#### 3) 실패했을 때
- 날짜를 비웠거나 올바른 날짜가 아니면 **저장되지 않고** 어디가 문제인지 안내합니다. (0-3의 기본 원칙)
- 이미 저장된 방학 날짜는 그대로 유지됩니다.

#### 4) 누가 볼 수 있나요? 누가 바꾸거나 지울 수 있나요?
- 점주만 볼 수 있고 입력·수정·삭제할 수 있습니다.

#### 5) 제대로 만들었는지 확인하는 방법
- 설정 화면에서 날짜를 입력·저장하면 **저장 안내가 나오는지** 봅니다.
- 서비스를 껐다 켜도 **입력한 날짜가 남아 있는지** 봅니다.
- 올바르지 않은 날짜를 넣으면 **저장되지 않는지** 봅니다.
- 두 개 이상의 기간을 입력해 **목록에 모두 보이는지**, 하나를 **수정**하면 날짜가 바뀌고 **삭제**하면 사라지는지 봅니다.
- 끝 날짜를 시작 날짜보다 앞으로 넣으면 **저장되지 않는지** 봅니다.
- 서로 겹치는 두 기간을 입력하면 **둘 다 목록에 저장되고**, 겹치는 날짜가 방학으로 한 번만(중복 없이) 계산되는지 봅니다.
- 방학 기간 안의 날짜와 밖의 날짜에서 **내일 예상 매출이 다르게 계산되는지** 봅니다.

### 7-2. 비밀번호 바꾸기

| 항목 | 내용 |

#### 입력 항목과 조건

| 입력 | 조건 |

1. 하단 메뉴에서 **설정**을 누릅니다.
2. 비밀번호를 바꾸는 곳에 **현재 비밀번호**를 입력합니다.
3. **새 비밀번호를 두 번** 입력하고 저장합니다.

#### 2) 정상일 때

- **화면에 보이는 것:** 바뀌었다는 안내입니다.
- 다음에 들어올 때부터 새 비밀번호를 입력해야 합니다.

#### 3) 실패했을 때
- 현재 비밀번호가 틀리거나, 새 비밀번호 두 번이 서로 다르거나, 조건에 맞지 않으면 **저장되지 않고** 이유를 알려줍니다. 이전 비밀번호가 그대로 유지됩니다. (0-3의 기본 원칙)

#### 4) 누가 볼 수 있나요? 누가 바꾸거나 지울 수 있나요?
- 비밀번호를 통과한 점주만 설정 화면에서 바꿀 수 있습니다. 비밀번호를 **지우거나 없애는 기능은 없습니다.**
- 비밀번호를 **잊어버렸을 때**는 화면에서 되찾는 기능이 없습니다. 사람이 직접 **서비스 설정을 고쳐서 다시 정합니다.** (점주 확인 완료)

#### 5) 제대로 만들었는지 확인하는 방법
- 비밀번호를 바꾸면 **이전 비밀번호로는 못 들어가고, 새 비밀번호로는 들어가지는지** 봅니다.
- 현재 비밀번호를 틀리게 넣거나, 새 비밀번호 두 번을 다르게 넣거나, 8글자보다 짧은 새 비밀번호를 넣으면 **저장되지 않고 이전 비밀번호가 유지되는지** 봅니다.

## 8. 화면 이동과 "데이터가 더 필요해요" 안내

### 8-1. 하단 메뉴

| 메뉴 | 열리는 화면 |
|---|---|
| 홈 | 화면 A (카드 4개) |
| 파일 올리기 | 화면 C |
| 설정 | 화면 E |

- 메뉴는 **세 개 그대로**입니다. "확인한 항목"은 메뉴가 아니라 홈 카드 안의 링크로 들어갑니다.
- 비밀번호 화면(D)은 메뉴가 아니라 들어올 때 한 번 나옵니다.
- **확인 방법:** 휴대폰에서 세 메뉴를 차례로 눌러 해당 화면이 열리는지, 홈에서 항목을 눌러 화면 B가 열리는지 봅니다.

### 8-2. 데이터가 적은 동안의 안내

- 해당하는 카드: **확인이 필요한 대분류, 같은 요일 비교, 내일 예상 매출**
- 카드 자리는 **그대로 유지**하면서 **"데이터가 더 필요해요"** 와 진행 상황을 보여줍니다. (예: "같은 요일 비교는 ○일 더 쌓이면 보여요")
- 몇 일 치부터 보여줄지는 설계 단계에서 확정합니다. (PRD 미정 7번)
- 이 상태는 **오류가 아닌 정상**입니다. 오늘 총매출·판매수량 같은 비교가 필요 없는 숫자는 그대로 보입니다.
- **확인 방법:** 파일을 처음 올린 직후 해당 카드에서 안내와 진행 상황이 보이는지, 데이터가 충분히 쌓이면 실제 결과로 바뀌는지 봅니다.

### 구현하면서 정한 세부 사항 (Phase 3)

PRD·spec에 숫자가 정해져 있지 않아 개발하면서 정한 값입니다. 다르게 하고 싶으면 알려 주세요. (설계 단계에서 확정하기로 했던 PRD 미정 7번의 일부입니다)

- **"평소"의 기준:** 오늘보다 앞선 **같은 요일**, 그중 **같은 시각까지의 매출**끼리 최근 **4번**의 평균입니다. 마감 시각이 다르면 누적 금액이 달라 비교가 틀어지므로, 시각이 다른 날은 비교에서 빼고 "마감 시각이 달라서 뺀 날이 N번 있어요"라고 알려줍니다.
- **보여주기 시작하는 데이터 양:** 위 조건의 같은 요일 데이터가 **3번 이상** 쌓이면 비교를 보여줍니다. 모자라면 "데이터가 더 필요해요 (1/3, 2번 더 필요)"와 진행 점을 보여줍니다.
- **즉석식품의 "평소 범위":** 같은 조건의 최근 최대 4번 중 **가장 적었던 값~가장 많았던 값**입니다. 오늘이 그 범위보다 크면 "평소보다 많음", 작으면 "평소보다 적음", 안이면 "평소 수준"입니다.
- **변화율:** (오늘 − 평소) ÷ 평소입니다. 평소가 0이면 "비교 불가"로 보여줍니다.
- **파일에 없는 대분류:** 간편식사·즉석조리 줄이 파일에 없으면 0개로 봅니다.
- **아직 만들지 않은 카드:** "확인이 필요한 대분류"와 "내일 예상 매출"은 자리를 잡고 **"준비 중"** 이라고 보여줍니다. ("데이터가 더 필요해요"와 구분합니다)

### 구현하면서 정한 세부 사항 (Phase 4)

> 계산 방식을 식과 예시까지 자세히 정리한 문서: [calculation.md](calculation.md)

점주와 정한 것과 개발하면서 정한 값입니다. 다르게 하고 싶으면 알려 주세요. (PRD 미정 7번 중 이상치 부분)

**점주와 정한 것**
- **홈 목록에 올리는 범위:** 가장 최근 올린 날짜로부터 **7일 안**의 이상한 날 중, 아직 "확인함·정상"을 누르지 않은 것입니다. 오래된 이상은 목록에서 빠지고, 그래프에는 계속 표시됩니다.
- **판단 기준:** 대분류의 **하루 매출금액**입니다.
- **목록은 대분류 단위, 확인은 날짜 단위입니다.** 홈에는 "담배"처럼 대분류 이름 한 줄이 올라오고, 그 안에 이상한 날이 날짜별로 보입니다. 목록의 "확인함·정상"은 그 대분류의 **지금 보이는 이상한 날을 한꺼번에** 확인 처리하고, 그래프 화면에서는 날짜 하나씩 처리하거나 취소할 수 있습니다.
- **민감도는 "보통"**, **최소 데이터는 같은 요일 3번**입니다. 기록이 쌓이면 최근 4번으로 자르지 않고 **쌓인 기록을 모두** 평소에 반영합니다.

**개발하면서 정한 값** (`backend/app/anomalies.py` 맨 위 숫자만 바꾸면 전체에 반영됩니다)
- **대분류마다 자기 평소와 따로 비교합니다.** 평소 = 그날보다 앞선 **같은 요일, 같은 시각까지**의 기록 전부. 마감 시각이 다른 날은 평소에서 뺍니다.
- **점수** = (그날 금액 − 평소 중간값) ÷ 흩어진 정도. 중간값과 흩어진 정도(중간값 기반)를 써서 한 번 튄 값에 덜 흔들립니다. 점수가 **3 이상**이고 차이가 **5,000원 이상**이면 이상한 날입니다. 흩어진 정도에는 하한(평소의 15%, 1,000원)을 두어 기록이 너무 비슷해도 작은 차이에 경고가 뜨지 않게 했습니다.
- **파일에 줄이 없는 대분류**는 그날 0원으로 봅니다. (담배 줄이 갑자기 없으면 "평소보다 적음"으로 올라옵니다)
- **거의 늘 0인 대분류**(평소의 절반 이상이 0원, 예: 복권)는 **안 팔린 날을 이상으로 보지 않고**, 팔린 날만 팔렸을 때의 금액끼리 비교합니다. 한 번도 안 팔리던 대분류는 **20,000원 이상** 팔릴 때만 올립니다.
- **그래프:** 최근 60일, 실선 = 실제, 점선 = 같은 요일 평소(중간값). 이상한 날은 ⚠ 표시(확인한 날은 ✓)와 "많음/적음" 말풍선을 붙입니다. 평소 기록이 3번 미만이던 앞쪽 날들은 판단하지 않아 점선이 없습니다.
- **가상 데이터 시뮬레이션:** 평소 흔들림 25% 정도의 대분류 15개에서 정상인데 뜨는 경고는 하루 약 1건(기록 4번 기준), 평소의 2.5배인 급증은 거의 100% 잡힙니다. 실제 파일이 쌓이면 이 숫자를 다시 조정합니다.
- **AI 설명 자리:** Phase 5에서 채웁니다. 지금은 **숫자 근거**(그날 금액, 평소 금액, 변화율)만 보입니다.
- **저장:** "확인함·정상" 기록은 대분류+날짜 한 건씩 저장합니다. 같은 항목을 두 번 눌러도 한 건입니다. 저장이 실패하면 항목은 목록에 그대로 남고 실패 안내가 나옵니다.
- **덮어쓰기:** 같은 날짜 파일을 덮어쓰면 그 날짜의 확인 기록이 모두 지워지고 새 숫자로 다시 판단합니다.

**화면 문구와 홈 구성 변경 (Phase 4 이후, 점주 요청)** — 위 설명에서 쓴 말과 화면에 보이는 말이 다릅니다.
- 화면에서는 "이상한 날"을 **"판매 변화가 큰 날"**, "확인함·정상"을 **"운영 상황 기록"**, "확인이 필요한 대분류"를 **"확인할 사항"**, "즉석식품 요약"을 **"집중 관리 식품군"**이라고 부릅니다. 동작은 같습니다. (입력할 글자는 없고, 대분류+날짜 하나씩 기록하며 취소할 수 있습니다)
- 홈은 **매출 요약 → 확인할 사항 → 집중 관리 식품군** 세 영역이고, 날짜·집계 시각은 맨 위에 한 번만 보입니다. 준비 중인 카드는 홈에서 숨깁니다. ([design.md](design.md)의 "홈의 구성" 참고)
- 확인할 사항의 **항목 한 줄을 누르면 상세 화면**이 열리고, 기록하는 버튼은 **상세 화면**에 있습니다. (홈 목록에서 한꺼번에 기록하는 버튼은 없어졌습니다)

**비교 기준과 운영 상황 기록 (UI 개선 이후)** — 계산 방식은 바꾸지 않고, 어떤 기준인지 화면에 밝혔습니다.
- **홈 매출 요약(총매출·판매 수량):** 분석 날짜 이전, 같은 요일·같은 시각까지 집계한 **최근 4번의 평균**. 사용한 날짜는 "비교 기준" 버튼에서 확인합니다.
- **확인할 사항·상세 화면(대분류):** 분석 날짜 이전, 같은 요일·같은 시각까지 집계한 **전체 기록의 중간값**. 평소 대부분 0원인 대분류는 **팔린 날만의 중간값**입니다. 화면에 "같은 요일 N번의 중간값"과 날짜 목록을 밝힙니다.
- **집중 관리 식품군:** 최근 4번의 **가장 적었던 값~가장 많았던 값**.
- 세 기준은 **쓰는 목적이 달라서** 서로 다릅니다. (총매출은 안정적인 평균, 대분류는 한 번 튄 날에 덜 흔들리는 중간값) 어느 화면에서도 분석 날짜 **이후** 자료는 쓰지 않고, 비교할 자료가 3번 미만이면 정상·이상을 판정하지 않고 "판단 자료 부족"을 보여줍니다.
- **표시 오류 수정:** 평소 대부분 0원인 대분류의 그래프 점선이 판정에 쓴 기준(팔린 날의 중간값)과 달라 0원으로 그려지던 것을 같은 값으로 맞췄습니다. 판정 결과는 그대로입니다.
- **운영 상황 기록:** 상세 화면에서 "당시 특이사항이 있었나요?"에 **행사·진열 변경 / 단체 구매 / 입고·품절 관련 사항 / 데이터 확인 필요 / 기타 / 모르겠어요** 중 고르고(여러 개 가능, "모르겠어요"는 단독), 메모(선택, 300자)를 적어 저장합니다. 선택은 하나 이상 필요합니다. **점주가 입력한 기록**이며 통계로 확인된 원인으로 쓰지 않습니다. 저장한 뒤에도 수정·취소할 수 있습니다. 같은 날짜를 덮어쓰면 이 기록도 지워집니다.

**총매출 분석 (홈 매출 요약의 상세 화면, 점주 요청)**
- 홈 "매출 요약" 카드의 **"총매출 자세히 보기"**로 들어갑니다. 점주가 올린 **그 시각까지**의 총매출을, 같은 시각까지 집계한 **이전 모든 날(요일 구분 없음)**의 기록과 비교합니다. (점주 요청: 굳이 같은 요일일 필요가 없음) (마감 시각이 다른 날은 누적 금액이 달라 비교와 그래프에서 뺍니다)
- **그래프:** 같은 시각까지 집계한 날들의 날짜별 총매출 시계열입니다. 평소 중심값(점선)과 95% 예상 범위(가는 점선)를 함께 그립니다. 오늘 점이 강조됩니다. 올리지 않은 날은 0원으로 채우지 않고 선을 끊습니다.
- **통계 판단 (점주와 정한 방식):** 쌓인 기록 **전부**(요일 구분 없이)로 평소의 분포를 그리고, 오늘 값이 그 분포의 어디에 놓이는지로 판단합니다. 기록이 쌓일수록 분포가 정교해집니다.
  - 자료: 오늘 **이전**, 같은 시각까지 집계한 모든 날의 총매출 전부. 요일에 따른 차이도 평소의 흔들림에 들어가므로 예상 범위가 넓어질 수 있습니다. **3번 미만이면 "판단 자료 부족"**이고 정상·이상을 판정하지 않습니다. 5번 미만이면 "참고용"을 함께 표시합니다.
  - 분포: 매출은 몇 %씩 흔들리는 성질이 있어 **비율(로그) 기준 정규분포**로 봅니다. 평소 범위가 0원 아래로 내려가지 않습니다. 0원인 날이 있으면 금액 그대로 계산합니다.
  - 판정: Student t **예측구간 검정**(양쪽, 유의수준 5%). t = (오늘 − 평균) ÷ (표준편차 × √(1 + 1/n)), 자유도 n − 1. 95% 범위를 벗어나면 "통계적으로 유의미한 증가/감소", 안이면 "유의미한 증가·감소는 없어요". 기록이 적으면 t 분포가 범위를 넓혀 신중하게 판정하고, 쌓이면 좁아집니다. 기록에 변동이 전혀 없으면 판정하지 않습니다.
  - 함께 계산하는 것: 비교 기준 금액(비율 기준이면 **기하평균**, 0원 이하 기록이 있으면 평균), 95% **예측구간**(하루 매출 하나가 들어올 것으로 보는 범위. 평균의 신뢰구간이 아님), 분포 안의 위치(상위·하위 %), "이전 N번 중 오늘보다 낮았던 날", p값. **p값은 "이전 기록의 분포가 맞다고 가정할 때 오늘만큼 벗어난 값이 나올 확률"이며, 이번 변화가 우연일 확률이나 원인을 뜻하지 않습니다.**
  - 기준이 다른 곳: 홈 매출 요약은 **같은 요일 최근 4번 평균**, 이 화면은 **요일 구분 없이 쌓인 전체의 분포**입니다. 화면에 그 차이를 밝힙니다.
  - t 분포는 외부 라이브러리 없이 직접 계산하며 표준표 값(자유도 1~30)과 일치하는지 시험합니다. 계산·판정은 `backend/app/sales_detail.py`, `backend/app/stats.py`입니다.

**총매출 분석 화면의 구성 (점주용 재구성)** — 통계를 모르는 점주도 이해하도록 정보를 **세 단계**로 나눕니다. 계산은 그대로이고 화면만 바뀝니다.

| 단계 | 어디에 | 보이는 것 |
|---|---|---|
| 1. 기본 화면 | `/sales` | 분석 날짜·집계 시간, 총매출(가장 크게), 비교 기준 대비 금액 차이, 증가율(보조), **쉬운 한 줄 해석**, 최근 매출 흐름 그래프(판매선과 선택 날짜의 점) |
| 2. 비교 근거 | 기본 화면의 "어떤 기록과 비교했나요?" 펼치기 | 비교 기간·기록 수, 요일을 구분하지 않는다는 점, 비교 기준 금액의 계산 방식(기하평균/평균), 주요 한계(연휴·행사가 섞임, 미수집은 0원이 아님, 기록이 적으면 참고용, 홈과 기준이 다름) |
| 3. 분석 상세 | `/sales/analysis` ("분석 상세 보기") | 통계 방법, 95% 예측 범위, 오늘의 위치(상위·하위 %), 기록 중 오늘보다 낮았던 날, t 값·자유도·p값, 가정과 검증 정보 |

- **한 줄 해석은 실제 탐지 결과에서 나옵니다.** 금액 증감만으로 판정하지 않습니다. 증가·감소의 방향은 비교 기준 금액과의 차이로, "눈에 띄게 높음/낮음"은 탐지 기준(p값 0.05 미만) 초과로 정해집니다.

| 분석 결과 | 기본 화면 문구 |
|---|---|
| 증가했지만 탐지 기준 안 | 매출은 늘었지만, 평소 변동 범위를 크게 벗어나지는 않았어요. |
| 감소했지만 탐지 기준 안 | 매출은 줄었지만, 평소 변동 범위를 크게 벗어나지는 않았어요. |
| 상방 탐지 기준 초과 | 이전 기록과 비교해 매출이 눈에 띄게 높아요. 행사나 단체 구매가 있었는지 확인해 보세요. |
| 하방 탐지 기준 초과 | 이전 기록과 비교해 매출이 눈에 띄게 낮아요. 입고·품절이나 운영 변동이 있었는지 확인해 보세요. |
| 자료 부족 | 비교할 기록이 아직 부족해요. 자료가 더 쌓이면 판매 변화를 확인할 수 있어요. |
| 기록의 변동 없음 | 비교한 기록의 매출이 모두 같아서 변화를 판단하기 어려워요. |

- **쓰지 않는 표현:** "문제없음", "정상 영업", 원인을 확정하는 말. 탐지 결과는 통계적 판단이며 매장 운영의 정상·비정상을 뜻하지 않습니다.
- **기본 화면에서 뺀 것:** "통계적으로 유의미한 증가·감소", 평소 중심값, 95% 범위 수치, 상위 %, "오늘보다 낮았던 날", p값, 긴 통계 설명. (분석 상세로 옮겼습니다) "이 정도 차이가 우연히 나올 확률"이라는 문구는 p값의 뜻과 달라 없앴습니다.
- **그래프:** 기본은 판매선과 선택 날짜의 점·금액만 보입니다. 비교 기준선과 평소 변동 범위는 **"비교 범위 보기"**를 눌렀을 때만 나옵니다. 숫자는 그래프에 쓰지 않습니다.
- **자료 부족·기록의 변동 없음처럼 결과를 쓸 수 없는 조건은 펼치기 안에 숨기지 않고 기본 화면에 표시합니다.** 기록이 5번 미만이면 "참고용"이라고 기본 화면에 함께 적습니다.
- **확인이 필요한 경우에만** 상단 해석 옆에 앰버 ⚠ 아이콘이 붙고, 아래에 "확인해 볼까요?"와 앰버 버튼 하나("확인할 사항 보기")가 나옵니다.
- **과거 관측 범위:** 홈 "집중 관리 식품군"의 최솟값~최댓값은 통계적 범위가 아니라 최근 같은 요일 4번에서 실제로 나온 값의 범위이므로 "과거 관측 범위"라고 부릅니다.
- **홈과의 관계:** 홈 매출 요약은 "같은 수요일 기준"(같은 요일 최근 4번 평균), 이 화면은 "이전 기록의 비교 기준"(요일 구분 없이 쌓인 전체)입니다. 이름과 계산이 다르다는 점을 화면에 밝힙니다.
