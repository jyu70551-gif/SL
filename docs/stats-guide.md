## 1. 시연용 데이터는 어떻게 만들었나 (데이터 증강)

### 왜 필요했나
실제 데이터가 월·화·수 23일뿐이라 화면, 탐지, AI가 **데이터가 많을 때 어떻게 동작하는지** 볼 수 없었습니다. 그래서 별도의 가짜 데이터를 만들었습니다. 실제 DB와는 완전히 분리되어 있습니다.

### 한 줄 요약
> 실제 23일을 보고 "이 가게의 평범한 날은 대략 이런 모양"이라는 **간단한 모형**을 만든 뒤, 그 모형에서 날짜를 무작위로 뽑아 빈 날을 채웠습니다.

실제 23일은 **그대로** 두고, 빈 날짜(약 278일)만 가짜로 채웠습니다.

### 단계별 설명

**① 실제 데이터에서 읽어낸 것 (통계로 추정)**

| 읽어낸 것 | 쉬운 설명 | 예시 비유 |
|---|---|---|
| 팔린 날 비율 | 분류마다 "23일 중 며칠이나 팔렸나" | 주류가 23일 중 20일 팔렸으면 약 87% |
| 팔린 날의 금액 분포 | 팔린 날의 금액이 어느 정도 범위에서 움직이나 | 담배는 늘 비슷하고, 간편식사는 들쭉날쭉 |
| 단가 | 수량 = 금액 ÷ 평균 단가 | |
| 하루 전체 흔들림 | 어떤 날은 모든 분류가 같이 잘 팔리고, 어떤 날은 같이 안 팔림 | 비 오는 날 전체가 줄어드는 느낌 |
| 월·화·수 요일 차이 | 요일마다 평균이 다른 정도 (절반만 반영) | 아래 설명 |

**② 왜 "로그"를 쓰나**
매출 금액은 작은 날은 비슷한데, 대박 나는 날은 크게 튑니다. 그래서 평균을 내면 대박 난 날 하나가 숫자를 끌어올립니다. **로그**를 취하면 "몇 원 차이"가 "몇 배 차이"로 바뀌어서 두 경우가 공평하게 비교됩니다.

- 1만 원 → 2만 원 (2배)과 10만 원 → 20만 원 (2배)을 같은 크기의 변화로 봅니다.
- 이렇게 로그를 취한 값이 종 모양(좌우 대칭)으로 퍼져 있다고 가정하는 것을 **로그정규분포**라고 합니다.
- **이 종 모양은 제가 가정한 것**입니다. 모양은 가정이고, 종의 가운데 위치와 퍼진 정도만 실제 데이터에서 계산했습니다.

**③ 하루 전체 흔들림 맞추기 (보정)**
분류마다 따로 무작위로 뽑으면 총매출이 실제보다 덜 흔들립니다. (한 분류가 올라가면 다른 분류가 내려가며 상쇄되기 때문입니다) 그래서 "그날 전체가 함께 오르내리는 정도"를 따로 만들어 곱했고, **가짜 총매출의 흔들림이 실제와 같아지도록** 크기를 조절했습니다.

- 확인 결과 실제 평범한 날은 0.31, 가짜 평범한 날은 0.30으로 거의 같았습니다. (로그 기준 표준편차)

**④ 제가 직접 정한 값 (통계적 근거 없음)**
실제에 없는 요일(목·금·토·일)과 특수일은 데이터로 알 수 없어서 **제가 숫자를 정했습니다.**

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 목·금·토·일 요일 효과 | 1.00 / 1.15 / 1.10 / 0.90 | 없음 (그럴 법하다는 가정) |
| 장날(3·8·13·18·23·28일) | +8% | 없음 |
| 공휴일 | −15% | 없음 |
| 설·추석 연휴 | −55% | 없음 |

이 값들은 [make_lab_data.py](../backend/tools/make_lab_data.py) 맨 위 `ASSUMED`에 모여 있고, 바꿔서 다시 만들 수 있습니다.

**⑤ 일부러 넣은 이상 (정답지)**
탐지가 잘 맞는지 확인하려면 **정답을 아는 이상**이 필요합니다. 그래서 급증(2.5~4.5배), 급감(0.1~0.4배), 품절(0원)을 약 40건 넣고 정답 목록으로 따로 저장했습니다.

- 평소와의 차이가 8,000원 이상인 의미 있는 크기만 넣었습니다. (탐지가 5,000원 미만 차이는 일부러 무시하는데, 작은 분류의 이상을 정답에 넣으면 평가가 불공정해지기 때문)
- 실제 날에는 넣지 않았고, 휴일에도 넣지 않았습니다.

**⑥ 가짜 점주 기록**
"이전 기록" 기능을 시험하려고 일주일보다 오래된 이상의 약 70%에 가짜 운영 기록을 붙였습니다. 내용은 시연용으로 만든 것입니다.

**⑦ 이어지는 변화 (4장 실험용)**
하루짜리 이상 말고도, 4장의 실험에서는 "28일 동안 금액이 ×0.6~×1.6으로 이어지는 변화"를 따로 만들어 넣었습니다. 크기와 기간은 제가 정한 값입니다.

### 믿어도 되는 것과 안 되는 것
| 믿어도 되는 것 | 믿으면 안 되는 것 |
|---|---|
| 평범한 날의 분류별 금액 규모, 흔들리는 정도 | 목~일 매출이 월~수보다 높다/낮다 |
| 총매출의 하루하루 흔들림 | 장날이나 휴일에 얼마나 변하는가 |
| 탐지가 급증·급감을 잡는지에 대한 **대략적인 감** | 실제 가게에서의 정확한 탐지율 |
| 화면이 데이터가 많을 때 어떻게 보이는지 | 가짜 데이터로 만든 AI 문장의 내용 (실제 매장 이야기가 아님) |

> 한 문장으로: **"실제 분포를 단순하게 흉내 낸 연습용 데이터"** 입니다. 새로운 사실을 알려 주는 데이터가 아닙니다.

### 이런 질문에 답하는 법
- **"가짜 데이터에서 요일 효과가 보이는데 진짜 아닌가요?"** 제가 넣은 숫자가 되돌아 나오는 것입니다. 진짜가 아닙니다.
- **"더 정교하게 만들면 더 믿을 수 있나요?"** 근거가 실제 23일뿐이라 모형만 복잡해질 뿐 정확해지지는 않습니다. 실제 데이터가 늘어야 정확해집니다.

## 2. 분류별 "평소와 다르다" 판단 (현재 앱)

### 하는 일
홈의 "확인할 사항"은 분류(담배, 음료 등)마다 **오늘 금액이 평소와 많이 다른지** 판단해서 올립니다.

### 어떻게 판단하나 (쉬운 버전)
1. **비교 대상을 고릅니다.** 같은 요일, 같은 시각까지의 매출만 모읍니다. (월요일 8시까지는 월요일 8시까지끼리 비교)
2. **"평소"를 정합니다.** 모은 금액들의 **중앙값**(크기순으로 줄 세웠을 때 한가운데 값)을 씁니다.
3. **"평소 흔들리는 정도"를 정합니다.** 각 금액이 중앙값에서 얼마나 떨어져 있는지의 **중앙값**을 씁니다. (MAD라고 부릅니다)
4. **점수를 냅니다.** `(오늘 금액 − 평소) ÷ 평소 흔들리는 정도`
5. **점수가 +3 이상이거나 −3 이하이고, 금액 차이가 5,000원 이상이면 올립니다.**

### 왜 평균이 아니라 중앙값을 쓰나
평균은 튀는 값 하나에 크게 흔들립니다.

> 월요일 담배 매출이 9만, 9만, 9만, 10만, **50만**(행사)이라면 평균은 약 17만이지만 중앙값은 9만입니다. 평균을 쓰면 다음 월요일의 평범한 9만이 "평소보다 훨씬 낮다"고 나옵니다.

중앙값은 튀는 값에 거의 영향을 받지 않아서 "평소"를 잘 나타냅니다.

### 왜 3점인가
점수 3은 "평소 흔들리는 정도의 3배만큼 떨어졌다"는 뜻으로, 평범한 날에는 드물게 나옵니다. 낮추면 더 많이 잡지만 오경보가 늘고, 올리면 오경보는 줄지만 놓치는 것이 늘어납니다. (5장 참고)

### 안전장치
- **기록이 3개 미만이면 판단하지 않습니다.** 근거가 너무 적습니다.
- **5,000원 미만 차이는 무시합니다.** 점수가 커도 금액이 작으면 점주에게 중요하지 않습니다.
- **거의 매일 0원인 분류**(예: 공코드대)는 "팔린 날"만 따로 보고 판단합니다.
- 흔들림의 하한(평소의 15%, 최소 1,000원)을 둡니다. 평소에 거의 똑같던 분류가 조금만 달라져도 점수가 폭발하는 것을 막기 위해서입니다.

### 알려진 약점 (시연 데이터에서 발견)
1. **급감과 품절을 거의 못 잡습니다.** 금액은 0 아래로 내려갈 수 없어서, 흔들림이 큰 분류에서는 0원이 돼도 점수가 −3에 못 미칩니다.
2. **이어지는 변화를 못 봅니다.** 매일 조금씩 낮아지는 변화는 하루하루는 평범해 보여서 알림이 나지 않습니다. (예: 평소의 80%로 계속 이어져도 놓침)
3. **0원이 많은 분류의 안 팔림을 못 봅니다.** 며칠째 안 팔려도 평소 0원과 구분되지 않습니다.

이 약점들을 보완하는 방법이 4장입니다.

## 3. 총매출 "평소 범위" 판단 (현재 앱)

### 하는 일
총매출 분석 화면은 오늘 총매출이 평소 범위 안인지를 알려 줍니다.

### 쉬운 설명
1. **같은 시각까지의 지난 총매출을 모읍니다.** 요일은 구분하지 않습니다. (요일별로 쪼개면 각 요일의 표본이 너무 적습니다)
2. **로그를 취합니다.** 위 1번의 이유와 같습니다. 배수로 비교하는 편이 공평합니다.
3. **"예측구간"을 만듭니다.** 지난 값들로 "다음 값은 이 범위 안에 95%의 확률로 들어올 것"이라는 범위를 계산합니다.
4. 오늘 값이 범위 **밖이면** "평소 범위를 벗어났다"고 표시합니다.

### 왜 t 분포를 쓰나
기록이 몇 개 안 될 때는 "평소 흔들림" 자체를 정확히 알 수 없습니다. 이 불확실성을 반영해서 범위를 **더 넓게** 잡아 주는 것이 **t 분포**입니다. 기록이 많아지면 범위가 자연스럽게 좁아집니다.

> 비유: 동네 식당을 3번 가 보고 "평균 대기 10분"이라고 하는 것과 100번 가 보고 하는 것은 확신이 다릅니다. t 분포는 3번 갔을 때 "10분 ± 많이"라고 말하게 해 줍니다.

### 95%의 뜻
평범한 날이 범위를 벗어날 확률이 5%라는 뜻입니다. 평범한 날의 20번 중 1번은 벗어나는 것이 정상입니다. (그래서 "벗어났다"가 곧 "문제가 있다"는 뜻은 아닙니다)

### 시연 데이터에서 확인한 것
평범한 날 중 실제로 벗어난 비율은 5%보다 낮은 **1.9%**였습니다. 즉 **보수적**입니다. 오경보는 적지만 진짜 변화를 덜 잡을 수 있습니다. 요일 효과와 휴일이 섞여 "평소 흔들림"이 실제보다 커 보이기 때문으로 추정합니다.

## 4. 시계열 이상치 탐지 — 새 방식 (실험)

> **상태: 앱에 반영되었습니다(2026-11-02).** 현재 방식(2장)과 함께 쓰며, 기록이 28일 이상 쌓이면 동작합니다. 앱 코드는 [detection.py](../backend/app/detection.py)이고, 휴일은 아직 반영하지 않습니다(휴일표 없음). 아래 평가는 시연 데이터(가짜)에서 한 것입니다.
> 평가 도구: [eval_changepoint.py](../backend/tools/eval_changepoint.py), [eval_rare.py](../backend/tools/eval_rare.py), [eval_final.py](../backend/tools/eval_final.py), [eval_sensitivity.py](../backend/tools/eval_sensitivity.py)

### 4-0. "시계열"과 "이상치 탐지"가 뭔가요
- **시계열**은 시간 순서대로 쌓이는 숫자입니다. 매일의 매출이 그렇습니다.
- **이상치 탐지**는 "이 숫자가 평소와 다른가?"를 판단하는 일입니다.
- 이상은 두 가지 모양이 있습니다.

| 모양 | 예 | 그림으로 |
|---|---|---|
| **하루짜리 튐** (점 이상) | 단체 구매로 하루만 3배, 하루 품절 | `10 10 10 10 **30** 10 10` |
| **이어지는 변화** (수준 이동) | 3주 전부터 매일 조금씩 줄어든 채로 유지 | `10 10 10 8 8 8 8 8 8 8` |

한 방식으로는 둘을 모두 잘 잡기 어렵습니다. 하루만 보는 방식은 두 번째를 못 보고, 누적하는 방식은 첫 번째를 늦게 봅니다.

### 4-1. 왜 새 방식이 필요한가 (현재 방식의 한계)
2장 끝에 적은 세 가지 약점입니다. 시연 데이터(가짜)에서 확인한 숫자는 아래와 같습니다.

| 상황 | 현재 방식이 알린 비율 |
|---|---|
| 하루짜리 급증 | 83% |
| 하루짜리 급감 | **9%** |
| 하루짜리 품절 | **8%** |
| 28일 이어지는 ×0.6 (매일 팔리는 분류) | **12%** |
| 28일 이어지는 ×0.8 | **5%** |
| 28일 내내 안 팔림 (0원이 많은 분류) | **1%** |

급증은 잘 잡지만 나머지는 거의 못 잡습니다. 이 결과는 가짜 데이터에서 나온 숫자이지만, "금액 차이 기준"과 "하루만 본다"는 **계산 방식의 성질**에서 오는 약점이라 실제 데이터에서도 비슷할 가능성이 높습니다.

### 4-2. 공통 준비 ① 로그로 바꾸기
금액을 `로그(금액 + 1,000)`으로 바꿔서 봅니다. (1,000을 더하는 것은 0원인 날도 계산할 수 있게 하려는 것입니다)

> 이유: 급증과 급감을 **같은 잣대**로 보기 위해서입니다.
> - 9만 원 → 27만 원 (3배 증가)와 9만 원 → 3만 원 (3분의 1)은 로그로 보면 크기가 같고 방향만 반대입니다.
> - 금액 그대로 보면 +18만과 −6만이라 급감이 훨씬 작아 보입니다. 이것이 현재 방식이 급감을 못 잡는 이유입니다.

### 4-3. 공통 준비 ② 요일 효과 빼기

**문제:** 월요일은 보통 높고 목요일은 보통 낮다면, 요일을 무시하고 비교하면 월요일이 늘 "높아 보이고" 목요일이 늘 "낮아 보입니다."

**방법:** 최근 기록으로 요일마다 "평소 대비 얼마나 높거나 낮은지"를 구해서 **먼저 빼 줍니다.** 그 뒤에 남은 차이(**잔차**)만 이상 판단에 씁니다.

> **예시 (가상 숫자):** 어떤 분류의 평소 수준은 10만 원이고, 최근 월요일들은 평소보다 평균 +20% 높았습니다.
> - 요일을 무시하면: 오늘 월요일 12만 원 → "평소보다 20% 높다"로 보입니다.
> - 요일 효과를 빼면: 월요일의 기대값은 12만 원이므로 → **정상입니다.**

**안전장치 (작은 표본 문제):** 같은 요일 기록이 몇 번 안 되면 효과가 우연일 수 있습니다. 그래서 **효과를 0쪽으로 당겨** 반영합니다. 같은 요일 기록이 4번이면 효과를 절반만 반영하고, 기록이 많아질수록 거의 전부 반영합니다.

> 예: 월요일 기록이 4번이고 +20%라면 +10%만 반영 → 월요일의 기대값은 11만 원.

**미래 정보를 쓰지 않습니다.** 오늘을 판단할 때는 **오늘 이전의 기록**만 씁니다. (오늘을 보고 "평소"를 정하면 오늘이 평소에 섞여서 이상이 숨겨집니다)

**평소 수준은 최근 84일**의 중앙값입니다. 수준이 바뀌고 오래 지속되면 새 수준이 "평소"가 됩니다. (이후 알림이 그치는 것은 의도된 동작입니다. "한번 알렸으니 새 평소를 받아들였다"는 뜻입니다.)

**휴일은 건너뜁니다.** 추석·설 같은 알려진 휴일은 기록에도 넣지 않고 알림도 내지 않습니다.

### 4-4. 점수 만들기 (z 점수)
요일 효과를 뺀 뒤 "오늘이 기대값에서 얼마나 떨어졌나"를 **흔들림의 몇 배**로 나타낸 숫자가 **점수(z)**입니다.

`z = (오늘 로그값 − 기대값) ÷ 평소 흔들리는 정도`

- z = 0이면 기대한 그대로, +2면 흔들림의 2배만큼 높음, −3이면 3배만큼 낮음입니다.
- 흔들림은 앞서 나온 MAD(중앙값 기반)를 쓰고, 너무 작아지지 않게 하한(0.15)을 둡니다.
- **기록이 28일 미만이면 판단하지 않습니다.**

### 4-5. 방법 A — Shewhart (하루 점수가 크면 알림)

**한 줄:** 하루만 보고, 점수가 기준을 넘으면 알립니다.

**이름의 유래:** 1920년대 공장 품질 관리에서 쓰던 관리도입니다. "제품 치수가 허용 범위를 벗어났나"를 하루하루 확인하는 방식입니다.

**판단 규칙:** `|z| ≥ c` 이고 평소와의 금액 차이가 5,000원 이상이면 알림. (보통 단계의 c는 4)

> **예시 (가상 숫자):** 어떤 분류의 목요일 기대값은 9만 원이고, 평소 흔들림은 0.25(로그 기준)입니다.
> - 오늘 금액이 2.5만 원이면: 로그 차이 ≈ ln(2.5/9) = −1.28 → z = −1.28 ÷ 0.25 ≈ **−5.1**
> - |z| = 5.1 ≥ 4 이고 금액 차이도 6.5만 원 → **알림 (급감)**.
> - 오늘 금액이 7만 원이면: ln(7/9) = −0.25 → z = −1.0 → 알림 없음.

**잘 잡는 것:** 하루짜리 큰 변화 (급증, 급감, 품절).
**못 잡는 것:** 점수가 기준에 못 미치는 **작은 변화가 이어질 때**. (z가 −1.5쯤인 날이 계속되어도 하루하루는 알림이 안 납니다.)

**기준 c를 4로 한 이유:** 현재 앱은 3입니다. 요일 효과를 빼서 점수가 정확해졌고, 중간 크기의 변화는 아래 CUSUM이 맡으므로 Shewhart는 **분명한 큰 변화만** 알리도록 높였습니다. (오경보를 줄이려는 선택이며, 통계로 정해진 값은 아닙니다)

### 4-6. 방법 B — CUSUM (조금씩 쌓아서 알림)

**한 줄:** 매일 "평소 대비 얼마나 낮았나/높았나"를 **누적**하다가, 쌓인 양이 기준을 넘으면 알립니다.

**이름의 유래:** Cumulative Sum(누적합)의 줄임말입니다. 1954년 E. S. Page가 제안했고, 공장 품질 관리에서 "서서히 어긋나는 기계"를 찾는 데 쓰였습니다.

> **비유:** 수도꼭지에서 물이 한 방울씩 새는 것은 하루만 보면 티가 안 납니다. 하지만 양동이에 모으면 차오르는 것이 보입니다. 비가 안 새는 날은 양동이가 비워지도록(0으로 돌아가도록) 만들어 둡니다.

**계산 방법 (낮아지는 쪽):**
1. 매일의 점수 z를 구합니다. (4-4)
2. **허용치 k (= 0.5)**를 뺍니다. "평소 흔들림의 절반까지의 차이는 변화로 치지 않겠다"는 뜻입니다.
3. `누적 = max(0, 어제 누적 − z − k)`. 낮은 날(z가 음수)은 누적이 쌓이고, 평범한 날은 줄어들며, **0 밑으로는 내려가지 않습니다.**
4. 누적이 **기준 h (보통 5)**를 넘으면 알리고 0으로 되돌립니다.
5. **높아지는 쪽**도 똑같이 따로 계산합니다. (`누적 = max(0, 어제 누적 + z − k)`)
6. 점수 z는 ±4로 **잘라서** 넣습니다. (한 번의 극단값이 누적을 혼자 채워 버리는 것을 막기 위해서입니다)

> **예시 (가상 숫자): 분류의 금액이 12일 동안 평소보다 조금씩 낮았다** (k = 0.5, h = 5)
>
> | 날 | 점수 z | 계산 (어제 누적 − z − 0.5) | 누적 | Shewhart(\|z\|≥4) | CUSUM(>5) |
> |---|---|---|---|---|---|
> | 1 | +0.2 | 0 − 0.2 − 0.5 → 음수라 0 | 0 | | |
> | 2 | −0.3 | 0 + 0.3 − 0.5 → 0 | 0 | | |
> | 3 | +0.4 | 0 | 0 | | |
> | 4 | −0.9 | 0 + 0.9 − 0.5 | 0.4 | | |
> | 5 | −1.2 | 0.4 + 1.2 − 0.5 | 1.1 | | |
> | 6 | −1.0 | 1.1 + 1.0 − 0.5 | 1.6 | | |
> | 7 | −1.5 | 1.6 + 1.5 − 0.5 | 2.6 | | |
> | 8 | −0.8 | 2.6 + 0.8 − 0.5 | 2.9 | | |
> | 9 | −1.1 | 2.9 + 1.1 − 0.5 | 3.5 | | |
> | 10 | −1.3 | 3.5 + 1.3 − 0.5 | 4.3 | | |
> | 11 | −1.0 | 4.3 + 1.0 − 0.5 | 4.8 | | |
> | 12 | −1.4 | 4.8 + 1.4 − 0.5 | 5.7 | | **알림** |
>
> - 점수는 하루하루 **−1.5 이내**라서 Shewhart(기준 4)는 한 번도 반응하지 않습니다.
> - CUSUM은 낮은 날들이 **쌓여서** 12일째에 알림을 냅니다.
> - 1~3일의 평범한 날에는 누적이 0으로 유지되어 알림이 없습니다. (오경보 방지)

**잘 잡는 것:** 며칠~몇 주 이어지는 **작은~중간 크기의 변화**.
**못 잡는 것:**
- 하루짜리 튐: 누적되기 전에 지나갑니다. (위 표처럼 점수가 한 번 크게 튀어도 k를 빼고 나면 누적은 몇 점뿐)
- 아주 작은 변화(약 −5%): 알아채는 데 몇 주가 걸립니다.

**기준 h로 알아채는 속도가 달라집니다.**
| h | 알아채는 속도 | 오경보 |
|---|---|---|
| 작게 (예: 4) | 빠름 | 많음 |
| 크게 (예: 8) | 느림 | 적음 |

> **중요:** CUSUM은 **요일 효과를 먼저 빼지 않으면** 요일 패턴이 누적되어 가짜 알림이 납니다. 그래서 4-3이 선행 조건입니다.

### 4-7. 방법 C — 결합 (Shewhart + CUSUM)
**둘 중 하나라도 알리면 알림**입니다. 공장 품질 관리에서도 표준으로 쓰는 조합입니다. (보통 단계는 Shewhart 4, CUSUM 5)

| 이상의 모양 | 누가 잡나 |
|---|---|
| 하루짜리 큰 튐 | Shewhart |
| 이어지는 작은~중간 변화 | CUSUM |
| 둘 다 | 먼저 넘는 쪽 |

**결과의 "가중치"는 따로 없습니다.** 둘을 섞어서 하나의 점수로 만드는 것이 아니라, 각자의 기준을 따로 둡니다.

### 4-8. 분류의 종류에 따라 방법이 달라집니다
분류마다 팔리는 날의 비율이 크게 다릅니다. 0원인 날이 많으면 위의 방법이 맞지 않습니다.

| 종류 | 기준 (팔린 날 비율) | 방법 |
|---|---|---|
| 거의 매일 팔림 | 90% 이상 | 4-2~4-7 (요일 제거 + Shewhart + CUSUM) |
| 0원이 많음 | 15~90% | **4-9** (두 부분으로 나눠 봄) |
| 거의 안 팔림 | 15% 미만 | **4-10** (평소보다 많이 팔릴 때만) |
| 한 번도 안 팔림 | 0% | 판단하지 않음 |

### 4-9. 0원이 많은 분류 — 두 부분으로 나눠서

**왜 따로 보나:** 0원인 날이 섞이면 금액의 "평소"와 "흔들림"이 의미를 잃습니다. 0원 날은 로그로 하면 아주 작은 값, 팔린 날은 훨씬 큰 값이어서 두 덩어리로 갈라지기 때문입니다.

**① 팔렸나 안 팔렸나 (비율에 대한 CUSUM)**
- 평소 팔린 날 비율을 최근 84일로 구합니다.
- "평소 비율" 가정과 "비율이 절반으로 줄었다" 가정 중 어느 쪽이 더 그럴듯한지를 **매일 점수로 더해 갑니다.** (낮아지는 쪽의 누적 점수가 기준 h를 넘으면 알림)
- 계산법은 4-6의 CUSUM과 같고, 매일 더하는 값만 다릅니다.
  - 안 팔린 날: 줄어든 비율이 더 그럴듯하므로 **+점수**
  - 팔린 날: 평소 비율이 더 그럴듯하므로 **−점수**

> **예시 (가상 숫자):** 평소 10일 중 8일 팔리던 분류(비율 0.8). "0.4로 줄었다"는 가정과 비교합니다.
> - 안 팔린 날의 점수: ln((1−0.4) ÷ (1−0.8)) = ln 3 ≈ **+1.10**
> - 팔린 날의 점수: ln(0.4 ÷ 0.8) = ln 0.5 ≈ **−0.69**
>
> 4일 연속 안 팔림이면 누적 4.39 → 보통 단계(h = 4)에서 **알림**. 3일 연속이면 3.30으로 알림이 아닙니다.
> 팔린 날이 섞이면 누적이 줄어듭니다. (예: 안 팔림, 팔림, 안 팔림 → 1.10 − 0.69 + 1.10 = 1.51)
>
> 민감도에 따라 알림이 나는 시점이 달라집니다. 높음(h = 3)은 3일 연속 안 팔림에서, 보통(h = 4)은 4일째, 낮음(h = 5)은 5일째입니다.

- 거의 매일 팔렸던 분류가 며칠째 안 팔릴 때 알려 줍니다. 품절이나 취급 중단의 신호일 수 있습니다.
- **요일 효과는 따로 빼지 않습니다.** 팔림 여부의 요일 효과는 크지 않다고 보고 단순하게 했습니다.

**② 팔린 날의 금액**
- **팔린 날만 모아서** 4-2~4-7을 그대로 적용합니다. (로그, 요일 제거, Shewhart + CUSUM)
- 팔린 날이 적어서 "평소"가 불안정하므로 **거의 매일 팔리는 분류보다 정확도가 떨어집니다.** (알림 문구도 "금액이 평소와 달랐다" 정도로 부드럽게 쓰는 것이 맞습니다)

**한계:**
- **안 팔린 날 하루짜리 품절은 잡을 수 없습니다.** 0원이 평소인 분류의 하루 0원은 정상과 구분되지 않습니다. 며칠 이어져야 ①이 잡습니다.
- 판매가 늘어나는 변화(안 팔리던 날에 팔림)는 느리게 알아챕니다.

### 4-10. 거의 안 팔리는 분류 — 평소보다 많이 팔릴 때만

**왜 다르게 하나:** 팔린 날이 몇 번 안 되어 요일 효과나 누적을 계산할 수 없습니다. 그래서 **과거 판매 기록과 직접 비교**하는 단순한 규칙을 씁니다.

**규칙 (팔린 날에만 판단, 오늘 이전 기록만 사용):**
1. **비교 기록:** 이 분류의 팔린 날이 5번 이상이면 그 기록. 5번 미만이면 거의 안 팔리는 분류들의 기록을 합친 것. 합친 기록도 없으면 수량 5개 이상일 때만 "많이 팔림"으로 봅니다.
2. **수량:** 이 분류 기록이 충분하면 **지금까지의 최대보다 많고, 평소(중앙값)의 2배 이상**이어야 합니다. 기록이 적으면 합친 기록의 상위 10% 이상(최소 5개)이어야 합니다.
3. **금액:** 기준 기록에서 **수량이 많았던 날(상위 25%)의 금액 중앙값 이상**이어야 합니다. (수량만 많고 금액이 작은 경우를 거릅니다)
4. **최소 금액 차이:** 평소와의 금액 차이가 최소 금액 이상이어야 합니다. (보통 3,000원. 현재 앱은 5,000원)

> **예시 (가상 숫자):** 어떤 분류는 팔린 날이 8번이고, 보통 하루 1개(최대 3개), 금액 중앙값 2,600원입니다. 수량이 많았던 날들의 금액은 5,000원쯤입니다.
>
> | 오늘 | 수량 | 금액 | 판단 |
> |---|---|---|---|
> | 평소 판매 | 1개 | 2,600원 | 최대(3)를 못 넘음 → 알림 없음 |
> | 조금 많음 | 4개 | 3,500원 | 수량은 최대 초과·평소의 2배 이상이지만 **금액이 5,000원에 못 미침** → 알림 없음 |
> | **많이 팔림** | 6개 | 15,000원 | 수량 6 > 3이고 평소의 2배 이상, 금액도 충분, 차이 12,400원 ≥ 3,000원 → **알림** |

**왜 "알림"에서 "평소 판매"는 빼나:** 거의 안 팔리는 분류는 한 번 팔릴 때마다 알림이 오면 점주가 알림을 무시하게 됩니다. 점주가 정한 대로 "평소보다 많이 팔릴 때만" 알립니다.

**한계:**
- 표본이 작아 3배 판매는 절반 정도만 잡습니다(5배는 거의 다 잡음).
- 한 번도 안 팔린 분류의 첫 판매는 합친 기록으로만 판단합니다.

### 4-11. 민감도 (낮음 / 보통 / 높음)
알림을 많이 받을지 적게 받을지를 점주가 고르는 **하나의 스위치**입니다. 세 방식의 기준값을 한꺼번에 바꿉니다.

| 민감도 | 현재 점수 | 매일 팔림 (Shewhart, CUSUM) | 팔린 날 비율 CUSUM | 거의 안 팔림 최소 금액 |
|---|---|---|---|---|
| 낮음 | 4.0 | 4.0 / 8.0 | 5.0 | 5,000원 |
| **보통** | 3.0 | 4.0 / 5.0 | 4.0 | 3,000원 |
| 높음 | 2.5 | 3.0 / 4.0 | 3.0 | 2,000원 |

**기준값이 작을수록** 더 작은 변화에도 알림이 나고, 알림이 늘어납니다. (민감도가 높다는 것은 알림이 잘 난다는 뜻입니다)

### 4-12. 종합 평가 (시연 데이터)

> **가짜 데이터에서의 숫자입니다.** 변화의 크기(×0.6, ×1.6 등)와 기간(28일)은 제가 정한 값입니다. 실제 가게의 정확도가 아닙니다.
> 비교는 같은 가짜 데이터(랩 DB 5개), 같은 이상으로 했습니다. "현재"는 지금 앱, "제안"은 위 새 방식만, "함께"는 둘 중 하나라도 알리면 알림입니다.

**① 하루 평균 알림 (평범한 날)**
| 현재 | 제안만 | 함께 |
|---|---|---|
| 0.37건 | 0.15건 | 0.47건 |

**② 하루짜리 이상을 그날 알린 비율**
| | 현재 | 제안만 | 함께 |
|---|---|---|---|
| 급증 | 83% | **47%** | 85% |
| 급감 | 9% | 42% | 44% |
| 품절 | 8% | 25% | 25% |

**③ 이어지는 변화를 28일 안에 알린 비율**
| 상황 | 현재 | 제안만 | 함께 |
|---|---|---|---|
| 매일 팔림, ×0.6 | 12% | 64% | 64% |
| 매일 팔림, ×0.8 | 5% | 49% | 49% |
| 매일 팔림, ×1.6 | 55% | 95% | 95% |
| 0원 많음, 28일 안 팔림 | 1% | 91% | 91% |
| 0원 많음, 팔린 날 60% 감소 | 3% | 80% | 80% |
| 0원 많음, 금액 ×1.6 | 86% | 71% | 91% |
| 거의 안 팔림, 평소의 3배 | 67% | 59% | 83% |

**읽는 법:**
- **제안만 쓰면** 오경보는 가장 적고 이어지는 변화에 강하지만, **하루짜리 급증을 47%밖에 못 잡습니다.** (0원이 많은 분류의 금액 판단이 약하기 때문)
- **현재만 쓰면** 급증은 잘 잡지만 급감, 품절, 이어지는 변화는 거의 못 잡습니다.
- **함께 쓰면** 두 약점이 서로 메워집니다. 대신 알림이 현재보다 조금 늘어납니다.

**④ 민감도별 ("함께" 구성)**
| | 현재 | 낮음 | 보통 | 높음 |
|---|---|---|---|---|
| 평범한 날 한 달(30일) 알림 | 11.9건 | **8.5건** | 14.9건 | 22.3건 |
| 급증을 그날 알림 | 83% | 73% | 85% | 89% |
| 급감을 그날 알림 | 9% | 37% | 44% | 63% |
| 품절을 그날 알림 | 8% | 25% | 25% | 42% |
| 매일 팔림 ×0.8, 알린 비율 (중앙 지연) | 5% (22일) | 35% (15일) | 49% (10일) | 60% (6일) |
| 28일 안 팔림, 알린 비율 (중앙 지연) | 1% (6일) | 84% (6일) | 91% (4일) | 96% (3일) |

- **낮음**: 알림이 현재보다 적은데도 급감, 품절, 이어지는 변화는 훨씬 잘 잡습니다. 하루짜리 급증은 73%로 현재보다 낮습니다.
- **보통**: 모든 항목에서 현재와 같거나 낫습니다. 한 달 알림이 약 3건 늘어납니다.
- **높음**: 놓침이 가장 적고 빨리 알아채지만 알림이 가장 많습니다. 보통에서 높음으로 갈 때 알림은 약 50% 늘어나고 급감은 19%p 오릅니다.
- 알림 건수는 **평범한 날**의 값이라, 실제 이상이 있는 날은 여기에 더해집니다.
- ①의 "현재 0.37건"과 ④의 "현재 11.9건 ÷ 30 ≈ 0.40건"이 조금 다른 것은, 평가를 따로 돌렸고 ④는 현재 방식의 점수를 소수 첫째 자리로 걸러 계산해 경계에서 아주 조금 어긋나기 때문입니다. 결론에는 영향이 없습니다.

### 4-13. 이 결과를 어디까지 믿을 수 있나

**믿을 수 있는 것 (계산 방식에서 나오는 성질):**
- 하루만 보는 방식은 이어지는 변화를 못 봅니다. 누적하는 방식은 하루짜리를 늦게 봅니다.
- 금액 차이 기준 점수는 급감을 구조적으로 못 잡습니다. (로그 기준에서는 대칭)
- 두 방식을 함께 쓰면 서로의 약점을 메웁니다.

**믿을 수 없는 것:**
- "85%를 잡는다", "한 달 15건"처럼 **구체적인 숫자**. 가짜 데이터에서 제가 정한 이상의 크기로 잰 값이고 실제 가게의 값이 아닙니다.
- 오경보 부담의 정도. 점주마다 다르고, 하루 0.5건이 괜찮은 점주도 3일만 와도 끄는 점주도 있습니다.
- 목~일 요일 효과, 장날, 휴일의 영향. 실제 데이터에 없어서 제가 정한 값입니다.

**그래서 앱에 넣는다면:**
1. 민감도 스위치를 점주가 조절할 수 있게 합니다. (기본은 보통)
2. "특이사항 없음", "도움이 됐어요" 응답으로 **실제 오경보율을 측정**합니다.
3. 측정한 값으로 기본값과 기준을 다시 정합니다.

## 5. 탐지가 잘 맞는지 확인하는 법 (재현율과 오경보)

### 두 가지 점수
탐지는 두 가지 실수를 합니다. 둘은 **서로 맞바꾸는 관계**라서 함께 봐야 합니다.

| 실수 | 뜻 | 숫자 이름 |
|---|---|---|
| 놓침 | 진짜 이상인데 안 올림 | **재현율**: 진짜 이상 중 잡은 비율 (높을수록 좋음) |
| 오경보 | 평범한데 올림 | **오경보율**: 평범한 것 중 잘못 올린 비율 (낮을수록 좋음) |

> 비유: 화재경보기가 예민하면 불은 놓치지 않지만 토스트를 구워도 울립니다. 둔하면 조용하지만 불을 놓칩니다.

### 어떻게 셌나
시연 데이터에는 정답을 아는 이상이 있으므로, "정답 중 몇 개를 올렸나(재현율)"와 "정답이 아닌 평범한 날 중 몇 개를 올렸나(오경보)"를 셀 수 있습니다. 시드를 바꿔 만든 DB 5개를 합쳐 계산했습니다.

### 초기 실험: 점수 기준만 바꿔 보기 (참고)
현재 점수에서 급감만 비율(로그) 기준으로 바꿔 본 첫 실험입니다. 4장의 방법들은 이 실험 이후에 나온 더 큰 구성입니다.

| 방식 | 재현율 | 급증 | 급감 | 품절 | 하루 오경보 |
|---|---|---|---|---|---|
| 현재 | 51% | 82/99 | 7/64 | 1/14 | 0.45건 |
| 급감만 로그 2.5 | 73% | 82/99 | 34/64 | 13/14 | 0.64건 |
| 급증 2.5, 급감 로그 2.0 | 81% | 88/99 | 42/64 | 13/14 | 0.84건 |

- 위로 갈수록 오경보가 적고 놓침이 많습니다.
- **어느 쪽이 좋은지는 통계가 아니라 점주의 판단입니다.** 오경보 한 건을 닫는 수고와 이상 한 건을 놓치는 손해를 견주어 정합니다.
- 이 숫자는 가짜 데이터의 가정 아래에서의 결과입니다. 실제 가게의 정확도가 아닙니다.

## 6. 데이터가 적으면 알 수 없는 것 (요일 효과)

### 질문
"월요일 매출이 화요일보다 높은가?"를 알려면 얼마나 많은 데이터가 있어야 할까요?

### 쉬운 설명
매출은 매일 들쭉날쭉합니다. 두 요일의 평균이 다르게 보여도, **우연히 그렇게 나온 것인지 진짜 차이인지** 구분하려면 날 수가 충분해야 합니다.

- 날이 적으면: 요일 차이가 **크게(약 2.2배 이상)** 나야 겨우 알아챕니다.
- 1.5배 정도의 차이를 알아채려면 요일마다 약 **32주** 치가 필요합니다.
- 지금은 요일당 약 8일이라서 작은 차이는 우연과 구분되지 않습니다.

> 비유: 동전을 3번 던져 앞면이 3번 나와도 동전이 이상하다고 할 수 없습니다. 100번 던져 80번 나와야 의심할 수 있습니다.

### 그래서
- 지금은 **요일을 구분하지 않고 비교하는 부분**(총매출)과 **같은 요일끼리 비교하는 부분**(분류별)을 나눠 두었습니다.
- 4장의 새 방식은 요일 효과를 **작은 표본에서 0쪽으로 당겨서** 반영합니다. (4-3) 요일 기록이 쌓일수록 자연스럽게 정확해집니다.
- Phase 7(내일 예상 매출)은 데이터가 쌓인 뒤에 요일 효과를 넣을지 판단합니다.

## 7. AI 점검 항목 순서 정하기 (우선순위 점수)

### 하는 일
이상이 여러 개일 때 "오늘의 점검"에는 **가장 중요한 2개**만 보여줍니다. 중요도는 세 가지를 섞은 점수로 정합니다.

`점수 = 0.5 × 이상 정도 + 0.3 × 금액 영향 + 0.2 × 최근성`

| 요소 | 뜻 |
|---|---|
| 이상 정도 (0.5) | 평소에서 얼마나 크게 벗어났나 (2번의 점수) |
| 금액 영향 (0.3) | 금액으로 얼마나 큰 차이인가 |
| 최근성 (0.2) | 얼마나 최근 일인가 |

- 점수가 0.35 미만이면 올리지 않습니다.
- **가중치 0.5/0.3/0.2는 통계로 구한 값이 아니라 제가 정한 값**입니다. 실제 사용하면서 조정하는 것이 맞습니다.
- AI는 이 순서를 바꾸지 않고, 정해진 항목을 **문장으로 풀어 쓰기만** 합니다. 계산은 모두 코드가 합니다.

## 8. 용어 사전

| 용어 | 쉬운 뜻 |
|---|---|
| 시계열 | 시간 순서대로 쌓이는 숫자 (매일의 매출 등) |
| 이상치 (이상) | 평소와 많이 다른 값 |
| 하루짜리 튐 (점 이상) | 하루만 평소와 다른 것 |
| 이어지는 변화 (수준 이동) | 어느 시점부터 평소 수준이 달라져서 이어지는 것 |
| 중앙값 | 크기순으로 줄 세웠을 때 한가운데 값. 튀는 값에 강함 |
| 평균 | 모두 더해서 개수로 나눈 값. 튀는 값에 약함 |
| 표준편차 | 값들이 평균에서 평균적으로 얼마나 떨어져 있나 (흩어진 정도) |
| MAD | 중앙값에서 떨어진 정도의 중앙값. 튀는 값에 강한 "흩어진 정도" |
| 로그 | 차이를 "몇 원"이 아니라 "몇 배"로 보게 바꾸는 변환 |
| 로그정규분포 | 로그를 취하면 종 모양이 되는 분포. 매출처럼 한쪽으로 길게 튀는 값에 맞음 |
| 요일 효과 | 요일마다 평소 수준이 다른 것 (월요일은 높음 등) |
| 잔차 | 요일 효과 등 "예상한 부분"을 빼고 남은 차이 |
| 점수 (z) | 평소에서 떨어진 정도를 "흔들림의 몇 배"로 나타낸 숫자 |
| Shewhart | 하루 점수가 기준을 넘으면 알리는 방식 (공장 품질 관리 출신) |
| CUSUM | 매일의 차이를 누적해서 기준을 넘으면 알리는 방식. 이어지는 변화에 강함 |
| 허용치 k | CUSUM에서 "이 정도 차이는 변화로 치지 않겠다"는 크기 |
| 기준 h | CUSUM의 누적이 이 값을 넘으면 알림 |
| 변화점 탐지 | 수준이 바뀐 시점을 찾는 방법들의 통칭 (CUSUM이 대표적) |
| 민감도 | 알림이 얼마나 잘 나는지. 높을수록 작은 변화에도 알림이 나고 알림이 늘어남 |
| 재현율 | 진짜 이상 중 탐지가 잡은 비율 |
| 오경보 | 이상이 아닌데 이상이라고 올린 것 |
| t 분포 | 데이터가 적을 때 불확실성을 반영해서 범위를 넓혀 주는 분포 |
| 예측구간 | "다음 값이 이 범위에 들어올 것"이라는 범위 (예: 95%) |
| 시드 | 무작위를 만드는 시작 숫자. 같은 시드면 같은 데이터가 나옴 |
| 보정 | 만든 데이터의 특징이 실제와 맞도록 크기를 조절하는 것 |
| 가정값 | 실제 근거 없이 사람이 정한 숫자 |

## 추가하는 법 (통계가 들어간 작업을 할 때)

새로운 통계적 방법(예측 모델, 새 탐지 기준, 표본 크기 계산 등)을 쓰면 이 문서에 **새 번호의 장**을 만들어 아래를 적습니다.

1. **하는 일** — 어떤 화면/기능에서 무엇을 위해 쓰는가
2. **쉬운 설명** — 통계 용어 없이, 가능하면 비유와 작은 예시로. **시계열 이상치 탐지처럼 판단 규칙이 있는 방법은 가상 숫자로 "어떻게 판단하는지"를 한 번 따라가 봅니다.**
3. **왜 이 방법인가** — 대안 대신 이걸 고른 이유
