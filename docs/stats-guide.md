## 1. 분류별 "평소와 다르다" 판단

### 하는 일
홈의 "확인할 사항"은 분류(담배, 음료 등)마다 **금액이 평소와 많이 다른지** 판단해서 올립니다. 판단은 **두 방식이 함께** 합니다. 둘 중 하나라도 알리면 알림이 올라가고, 같은 분류·같은 날에 둘 다 알리면 기존 방식의 설명을 보여 줍니다.

| 방식 | 잘 보는 것 | 언제 동작하나 |
|---|---|---|
| **기존 방식** (1-1) | 같은 요일과 비교한 하루짜리 큰 변화 | 같은 요일 기록이 3번 이상 |
| **이어지는 변화까지 보는 방식** (1-2 ~ 1-9) | 급감·품절, 며칠 이어지는 변화, 0원이 많은 분류의 안 팔림 | 기록이 28일 이상 |

### 1-1. 기존 방식: 같은 요일의 중앙값과 비교

**어떻게 판단하나**
1. **비교 대상을 고릅니다.** 같은 요일, 같은 시각까지의 매출만 모읍니다. (월요일 8시까지는 월요일 8시까지끼리 비교)
2. **"평소"를 정합니다.** 모은 금액들의 **중앙값**(크기순으로 줄 세웠을 때 한가운데 값)을 씁니다.
3. **"평소 흔들리는 정도"를 정합니다.** 각 금액이 중앙값에서 얼마나 떨어져 있는지의 **중앙값**을 씁니다. (MAD)
4. **점수를 냅니다.** `(오늘 금액 − 평소) ÷ 평소 흔들리는 정도`
5. **점수가 기준 이상이고 금액 차이가 5,000원 이상이면 올립니다.** 기준은 민감도에 따라 4.0(낮음), 3.0(보통), 2.5(높음)입니다.

**왜 평균이 아니라 중앙값을 쓰나**
평균은 튀는 값 하나에 크게 흔들립니다.

> 월요일 담배 매출이 9만, 9만, 9만, 10만, **50만**(행사)이라면 평균은 약 17만이지만 중앙값은 9만입니다. 평균을 쓰면 다음 월요일의 평범한 9만이 "평소보다 훨씬 낮다"고 나옵니다.

**왜 3점인가 (보통 단계)**
점수 3은 "평소 흔들리는 정도의 3배만큼 떨어졌다"는 뜻으로, 평범한 날에는 드물게 나옵니다. 낮추면 더 많이 잡지만 오경보가 늘고, 올리면 오경보는 줄지만 놓치는 것이 늘어납니다.

**안전장치**
- **같은 요일 기록이 3개 미만이면 판단하지 않습니다.** 근거가 너무 적습니다.
- **5,000원 미만 차이는 무시합니다.** 점수가 커도 금액이 작으면 점주에게 중요하지 않습니다.
- **거의 매일 0원인 분류**(예: 공코드대)는 "팔린 날"만 따로 보고 판단합니다.
- 흔들림의 하한(평소의 15%, 최소 1,000원)을 둡니다. 평소에 거의 똑같던 분류가 조금만 달라져도 점수가 폭발하는 것을 막기 위해서입니다.

**이 방식만으로는 잘 못 잡는 것**
- **급감과 품절**: 금액은 0 아래로 내려갈 수 없어서, 흔들림이 큰 분류에서는 0원이 돼도 점수가 기준에 못 미칠 수 있습니다.
- **이어지는 변화**: 매일 조금씩 낮아지는 변화는 하루하루는 평범해 보여서 알림이 나지 않습니다.
- **0원이 많은 분류의 안 팔림**: 며칠째 안 팔려도 평소 0원과 구분되지 않습니다.

이 약점은 아래 1-2 이후의 방식이 메웁니다.

### 1-2. "시계열"과 "이상치 탐지"가 뭔가요
- **시계열**은 시간 순서대로 쌓이는 숫자입니다. 매일의 매출이 그렇습니다.
- **이상치 탐지**는 "이 숫자가 평소와 다른가?"를 판단하는 일입니다.
- 이상은 두 가지 모양이 있습니다.

| 모양 | 예 | 그림으로 |
|---|---|---|
| **하루짜리 튐** (점 이상) | 단체 구매로 하루만 3배, 하루 품절 | `10 10 10 10 **30** 10 10` |
| **이어지는 변화** (수준 이동) | 3주 전부터 매일 조금씩 줄어든 채로 유지 | `10 10 10 8 8 8 8 8 8 8` |

한 방식으로는 둘을 모두 잘 잡기 어렵습니다. 하루만 보는 방식은 두 번째를 못 보고, 누적하는 방식은 첫 번째를 늦게 봅니다. 그래서 둘을 함께 씁니다.

### 1-3. 공통 준비 ① 로그로 바꾸기
금액을 `로그(금액 + 1,000)`으로 바꿔서 봅니다. (1,000을 더하는 것은 0원인 날도 계산할 수 있게 하려는 것입니다)

> 이유: 급증과 급감을 **같은 잣대**로 보기 위해서입니다.
> - 9만 원 → 27만 원 (3배 증가)와 9만 원 → 3만 원 (3분의 1)은 로그로 보면 크기가 같고 방향만 반대입니다.
> - 금액 그대로 보면 +18만과 −6만이라 급감이 훨씬 작아 보입니다. 이것이 기존 방식이 급감을 못 잡는 이유입니다.

### 1-4. 공통 준비 ② 요일 효과 빼기

**문제:** 월요일은 보통 높고 목요일은 보통 낮다면, 요일을 무시하고 비교하면 월요일이 늘 "높아 보이고" 목요일이 늘 "낮아 보입니다."

**방법:** 최근 기록으로 요일마다 "평소 대비 얼마나 높거나 낮은지"를 구해서 **먼저 빼 줍니다.** 그 뒤에 남은 차이(**잔차**)만 이상 판단에 씁니다.

> **예시 (가상 숫자):** 어떤 분류의 평소 수준은 10만 원이고, 최근 월요일들은 평소보다 평균 +20% 높았습니다.
> - 요일을 무시하면: 오늘 월요일 12만 원 → "평소보다 20% 높다"로 보입니다.
> - 요일 효과를 빼면: 월요일의 기대값은 12만 원이므로 → **정상입니다.**

**안전장치 (작은 표본 문제):** 같은 요일 기록이 몇 번 안 되면 효과가 우연일 수 있습니다. 그래서 **효과를 0쪽으로 당겨** 반영합니다. 같은 요일 기록이 4번이면 효과를 절반만 반영하고, 기록이 많아질수록 거의 전부 반영합니다.

> 예: 월요일 기록이 4번이고 +20%라면 +10%만 반영 → 월요일의 기대값은 11만 원.

**미래 정보를 쓰지 않습니다.** 오늘을 판단할 때는 **오늘 이전의 기록**만 씁니다. (오늘을 보고 "평소"를 정하면 오늘이 평소에 섞여서 이상이 숨겨집니다)

**평소 수준은 최근 84일**의 중앙값입니다. 수준이 바뀌고 오래 지속되면 새 수준이 "평소"가 됩니다. (이후 알림이 그치는 것은 의도된 동작입니다. "한번 알렸으니 새 평소를 받아들였다"는 뜻입니다.)

**휴일은 따로 빼지 않습니다.** 앱에는 아직 휴일표가 판단에 쓰이지 않습니다. 대신 알림이 난 날이 장날·공휴일·방학이면 알림 아래에 "참고: 이날은 공휴일(설날)이에요. 평소와 다를 수 있어요."라는 **한 줄만 붙입니다.** 알림 자체를 빼거나 바꾸지 않습니다. (1-10)

### 1-5. 점수 만들기 (z 점수)
요일 효과를 뺀 뒤 "오늘이 기대값에서 얼마나 떨어졌나"를 **흔들림의 몇 배**로 나타낸 숫자가 **점수(z)**입니다.

`z = (오늘 로그값 − 기대값) ÷ 평소 흔들리는 정도`

- z = 0이면 기대한 그대로, +2면 흔들림의 2배만큼 높음, −3이면 3배만큼 낮음입니다.
- 흔들림은 앞서 나온 MAD(중앙값 기반)를 쓰고, 너무 작아지지 않게 하한(0.15)을 둡니다.
- **기록이 28일 미만이면 판단하지 않습니다.**

### 1-6. 방법 A — Shewhart (하루 점수가 크면 알림)

**한 줄:** 하루만 보고, 점수가 기준을 넘으면 알립니다.

**이름의 유래:** 1920년대 공장 품질 관리에서 쓰던 관리도입니다. "제품 치수가 허용 범위를 벗어났나"를 하루하루 확인하는 방식입니다.

**판단 규칙:** `|z| ≥ c` 이고 평소와의 금액 차이가 최소 금액 이상이면 알림. (보통 단계의 c는 4, 최소 금액은 5,000원)

> **예시 (가상 숫자):** 어떤 분류의 목요일 기대값은 9만 원이고, 평소 흔들림은 0.25(로그 기준)입니다.
> - 오늘 금액이 2.5만 원이면: 로그 차이 ≈ ln(2.5/9) = −1.28 → z = −1.28 ÷ 0.25 ≈ **−5.1**
> - |z| = 5.1 ≥ 4 이고 금액 차이도 6.5만 원 → **알림 (급감)**.
> - 오늘 금액이 7만 원이면: ln(7/9) = −0.25 → z = −1.0 → 알림 없음.

**잘 잡는 것:** 하루짜리 큰 변화 (급증, 급감, 품절).
**못 잡는 것:** 점수가 기준에 못 미치는 **작은 변화가 이어질 때**. (z가 −1.5쯤인 날이 계속되어도 하루하루는 알림이 안 납니다.)

**기준 c를 4로 한 이유:** 요일 효과를 빼서 점수가 정확해졌고, 중간 크기의 변화는 아래 CUSUM이 맡으므로 Shewhart는 **분명한 큰 변화만** 알리도록 높였습니다. (오경보를 줄이려는 선택이며, 통계로 정해진 값은 아닙니다)

### 1-7. 방법 B — CUSUM (조금씩 쌓아서 알림)

**한 줄:** 매일 "평소 대비 얼마나 낮았나/높았나"를 **누적**하다가, 쌓인 양이 기준을 넘으면 알립니다.

**이름의 유래:** Cumulative Sum(누적합)의 줄임말입니다. 1954년 E. S. Page가 제안했고, 공장 품질 관리에서 "서서히 어긋나는 기계"를 찾는 데 쓰였습니다.

> **비유:** 수도꼭지에서 물이 한 방울씩 새는 것은 하루만 보면 티가 안 납니다. 하지만 양동이에 모으면 차오르는 것이 보입니다. 비가 안 새는 날은 양동이가 비워지도록(0으로 돌아가도록) 만들어 둡니다.

**계산 방법 (낮아지는 쪽):**
1. 매일의 점수 z를 구합니다. (1-5)
2. **허용치 k (= 0.5)**를 뺍니다. "평소 흔들림의 절반까지의 차이는 변화로 치지 않겠다"는 뜻입니다.
3. `누적 = max(0, 어제 누적 − z − k)`. 낮은 날(z가 음수)은 누적이 쌓이고, 평범한 날은 줄어들며, **0 밑으로는 내려가지 않습니다.**
4. 누적이 **기준 h (보통 5)**를 넘으면 알리고 0으로 되돌립니다.
5. **높아지는 쪽**도 똑같이 따로 계산합니다. (`누적 = max(0, 어제 누적 + z − k)`)
6. 점수 z는 ±4로 **잘라서** 넣습니다. (한 번의 극단값이 누적을 혼자 채워 버리는 것을 막기 위해서입니다)

> **예시 (가상 숫자): 분류의 금액이 12일 동안 평소보다 조금씩 낮았다** (k = 0.5, h = 5)
>
> | 날 | 점수 z | 계산 (어제 누적 − z − 0.5) | 누적 | Shewhart(\|z\|≥4) | CUSUM(>5) |
> |---|---|---|---|---|---|
> | 1 | +0.2 | 0 − 0.2 − 0.5 → 음수라 0 | 0 | | |
> | 2 | −0.3 | 0 + 0.3 − 0.5 → 0 | 0 | | |
> | 3 | +0.4 | 0 | 0 | | |
> | 4 | −0.9 | 0 + 0.9 − 0.5 | 0.4 | | |
> | 5 | −1.2 | 0.4 + 1.2 − 0.5 | 1.1 | | |
> | 6 | −1.0 | 1.1 + 1.0 − 0.5 | 1.6 | | |
> | 7 | −1.5 | 1.6 + 1.5 − 0.5 | 2.6 | | |
> | 8 | −0.8 | 2.6 + 0.8 − 0.5 | 2.9 | | |
> | 9 | −1.1 | 2.9 + 1.1 − 0.5 | 3.5 | | |
> | 10 | −1.3 | 3.5 + 1.3 − 0.5 | 4.3 | | |
> | 11 | −1.0 | 4.3 + 1.0 − 0.5 | 4.8 | | |
> | 12 | −1.4 | 4.8 + 1.4 − 0.5 | 5.7 | | **알림** |
>
> - 점수는 하루하루 **−1.5 이내**라서 Shewhart(기준 4)는 한 번도 반응하지 않습니다.
> - CUSUM은 낮은 날들이 **쌓여서** 12일째에 알림을 냅니다.
> - 1~3일의 평범한 날에는 누적이 0으로 유지되어 알림이 없습니다. (오경보 방지)

**잘 잡는 것:** 며칠~몇 주 이어지는 **작은~중간 크기의 변화**.
**못 잡는 것:**
- 하루짜리 튐: 누적되기 전에 지나갑니다. (위 표처럼 점수가 한 번 크게 튀어도 k를 빼고 나면 누적은 몇 점뿐)
- 아주 작은 변화(약 −5%): 알아채는 데 몇 주가 걸립니다.

**기준 h로 알아채는 속도가 달라집니다.**
| h | 알아채는 속도 | 오경보 |
|---|---|---|
| 작게 (예: 4) | 빠름 | 많음 |
| 크게 (예: 8) | 느림 | 적음 |

> **중요:** CUSUM은 **요일 효과를 먼저 빼지 않으면** 요일 패턴이 누적되어 가짜 알림이 납니다. 그래서 1-4가 선행 조건입니다.

**Shewhart와 CUSUM을 함께 씁니다.** 둘 중 하나라도 알리면 알림입니다. (공장 품질 관리에서도 표준으로 쓰는 조합입니다) 둘을 섞어서 하나의 점수로 만드는 것이 아니라 각자의 기준을 따로 둡니다.

| 이상의 모양 | 누가 잡나 |
|---|---|
| 하루짜리 큰 튐 | Shewhart |
| 이어지는 작은~중간 변화 | CUSUM |
| 둘 다 | 먼저 넘는 쪽 |

### 1-8. 분류의 종류에 따라 방법이 달라집니다
분류마다 팔리는 날의 비율이 크게 다릅니다. 0원인 날이 많으면 위의 방법이 맞지 않습니다.

| 종류 | 기준 (팔린 날 비율) | 방법 |
|---|---|---|
| 거의 매일 팔림 | 90% 이상 | 1-3 ~ 1-7 (요일 제거 + Shewhart + CUSUM) |
| 0원이 많음 | 15~90% | **1-8-1** (두 부분으로 나눠 봄) |
| 거의 안 팔림 | 15% 미만 | **1-8-2** (평소보다 많이 팔릴 때만) |
| 한 번도 안 팔림 | 0% | 판단하지 않음 |

#### 1-8-1. 0원이 많은 분류 — 두 부분으로 나눠서

**왜 따로 보나:** 0원인 날이 섞이면 금액의 "평소"와 "흔들림"이 의미를 잃습니다. 0원 날은 로그로 하면 아주 작은 값, 팔린 날은 훨씬 큰 값이어서 두 덩어리로 갈라지기 때문입니다.

**① 팔렸나 안 팔렸나 (비율에 대한 CUSUM)**
- 평소 팔린 날 비율을 최근 84일로 구합니다.
- "평소 비율" 가정과 "비율이 절반으로 줄었다" 가정 중 어느 쪽이 더 그럴듯한지를 **매일 점수로 더해 갑니다.** (낮아지는 쪽의 누적 점수가 기준 h를 넘으면 알림)
- 계산법은 1-7의 CUSUM과 같고, 매일 더하는 값만 다릅니다.
  - 안 팔린 날: 줄어든 비율이 더 그럴듯하므로 **+점수**
  - 팔린 날: 평소 비율이 더 그럴듯하므로 **−점수**

> **예시 (가상 숫자):** 평소 10일 중 8일 팔리던 분류(비율 0.8). "0.4로 줄었다"는 가정과 비교합니다.
> - 안 팔린 날의 점수: ln((1−0.4) ÷ (1−0.8)) = ln 3 ≈ **+1.10**
> - 팔린 날의 점수: ln(0.4 ÷ 0.8) = ln 0.5 ≈ **−0.69**
>
> 4일 연속 안 팔림이면 누적 4.39 → 보통 단계(h = 4)에서 **알림**. 3일 연속이면 3.30으로 알림이 아닙니다.
> 팔린 날이 섞이면 누적이 줄어듭니다. (예: 안 팔림, 팔림, 안 팔림 → 1.10 − 0.69 + 1.10 = 1.51)
>
> 민감도에 따라 알림이 나는 시점이 달라집니다. 높음(h = 3)은 3일 연속 안 팔림에서, 보통(h = 4)은 4일째, 낮음(h = 5)은 5일째입니다.

- 거의 매일 팔렸던 분류가 며칠째 안 팔릴 때 알려 줍니다. 품절이나 취급 중단의 신호일 수 있습니다.
- **요일 효과는 따로 빼지 않습니다.** 팔림 여부의 요일 효과는 크지 않다고 보고 단순하게 했습니다.

**② 팔린 날의 금액**
- **팔린 날만 모아서** 1-3 ~ 1-7을 그대로 적용합니다. (로그, 요일 제거, Shewhart + CUSUM)
- 팔린 날이 적어서 "평소"가 불안정하므로 **거의 매일 팔리는 분류보다 정확도가 떨어집니다.**

**한계:**
- **안 팔린 날 하루짜리 품절은 잡을 수 없습니다.** 0원이 평소인 분류의 하루 0원은 정상과 구분되지 않습니다. 며칠 이어져야 ①이 잡습니다.
- 판매가 늘어나는 변화(안 팔리던 날에 팔림)는 느리게 알아챕니다.

#### 1-8-2. 거의 안 팔리는 분류 — 평소보다 많이 팔릴 때만

**왜 다르게 하나:** 팔린 날이 몇 번 안 되어 요일 효과나 누적을 계산할 수 없습니다. 그래서 **과거 판매 기록과 직접 비교**하는 단순한 규칙을 씁니다.

**규칙 (팔린 날에만 판단, 오늘 이전 기록만 사용):**
1. **비교 기록:** 이 분류의 팔린 날이 5번 이상이면 그 기록. 5번 미만이면 거의 안 팔리는 분류들의 기록을 합친 것. 합친 기록도 없으면 수량 5개 이상일 때만 "많이 팔림"으로 봅니다.
2. **수량:** 이 분류 기록이 충분하면 **지금까지의 최대보다 많고, 평소(중앙값)의 2배 이상**이어야 합니다. 기록이 적으면 합친 기록의 상위 10% 이상(최소 5개)이어야 합니다.
3. **금액:** 기준 기록에서 **수량이 많았던 날(상위 25%)의 금액 중앙값 이상**이어야 합니다. (수량만 많고 금액이 작은 경우를 거릅니다)
4. **최소 금액 차이:** 평소와의 금액 차이가 최소 금액 이상이어야 합니다. (보통 3,000원)

> **예시 (가상 숫자):** 어떤 분류는 팔린 날이 8번이고, 보통 하루 1개(최대 3개), 금액 중앙값 2,600원입니다. 수량이 많았던 날들의 금액은 5,000원쯤입니다.
>
> | 오늘 | 수량 | 금액 | 판단 |
> |---|---|---|---|
> | 평소 판매 | 1개 | 2,600원 | 최대(3)를 못 넘음 → 알림 없음 |
> | 조금 많음 | 4개 | 3,500원 | 수량은 최대 초과·평소의 2배 이상이지만 **금액이 5,000원에 못 미침** → 알림 없음 |
> | **많이 팔림** | 6개 | 15,000원 | 수량 6 > 3이고 평소의 2배 이상, 금액도 충분, 차이 12,400원 ≥ 3,000원 → **알림** |

**왜 "평소 판매"는 알리지 않나:** 거의 안 팔리는 분류는 한 번 팔릴 때마다 알림이 오면 점주가 알림을 무시하게 됩니다. 점주가 정한 대로 "평소보다 많이 팔릴 때만" 알립니다.

**한계:**
- 표본이 작아 평소의 3배쯤 판매는 절반 정도만 잡고, 5배는 거의 다 잡습니다.
- 한 번도 안 팔린 분류의 첫 판매는 합친 기록으로만 판단합니다.

### 1-9. 민감도 (낮음 / 보통 / 높음)
알림을 많이 받을지 적게 받을지를 점주가 고르는 **하나의 스위치**입니다. (설정 화면의 "알림 민감도", 기본은 보통) 기존 방식과 새 방식의 기준값을 한꺼번에 바꿉니다.

| 민감도 | 기존 방식 점수 | 매일 팔림 (Shewhart, CUSUM) | 팔린 날 비율 CUSUM | 거의 안 팔림 최소 금액 |
|---|---|---|---|---|
| 낮음 | 4.0 | 4.0 / 8.0 | 5.0 | 5,000원 |
| **보통** | 3.0 | 4.0 / 5.0 | 4.0 | 3,000원 |
| 높음 | 2.5 | 3.0 / 4.0 | 3.0 | 2,000원 |

**기준값이 작을수록** 더 작은 변화에도 알림이 나고, 알림이 늘어납니다. (민감도가 높다는 것은 알림이 잘 난다는 뜻입니다) 알림이 너무 많으면 낮추고, 놓치는 것이 걱정되면 높여 보세요.

### 1-10. 장날·공휴일·방학은 "참고"로만 붙입니다
설정에서 저장한 장날, 공휴일, 방학은 판단을 바꾸지 않습니다. 알림이 난 날이 해당하면 알림 아래에 "참고: 이날은 장날이에요. 평소와 다를 수 있어요." 한 줄만 붙입니다. 진짜 문제를 놓치지 않기 위해 알림을 빼거나 기준을 바꾸지 않습니다.

### 믿어도 되는 것과 안 되는 것
**믿을 수 있는 것 (계산 방식에서 나오는 성질):**
- 하루만 보는 방식은 이어지는 변화를 못 봅니다. 누적하는 방식은 하루짜리를 늦게 봅니다. 그래서 둘을 함께 씁니다.
- 금액 차이 기준 점수는 급감을 구조적으로 못 잡습니다. (로그 기준에서는 대칭)

**믿을 수 없는 것:**
- 알림 정확도의 구체적인 숫자. 앱에는 실제 오경보율을 잴 자료가 아직 없습니다. 점주가 "특이사항 없음", "도움이 됐어요"로 남기는 응답이 쌓이면 그 값으로 기본값과 기준을 다시 점검할 계획입니다.
- 오경보 부담의 정도. 점주마다 다릅니다.
- 실제 자료가 28일보다 적으면 새 방식은 아직 동작하지 않습니다.

## 2. 총매출 "평소 범위" 판단

### 하는 일
총매출 분석 화면은 오늘 총매출이 평소 범위 안인지를 알려 줍니다.

### 쉬운 설명
1. **같은 시각까지의 지난 총매출을 모읍니다.** 요일은 구분하지 않습니다. (요일별로 쪼개면 각 요일의 표본이 너무 적습니다)
2. **로그를 취합니다.** 1-3의 이유와 같습니다. 배수로 비교하는 편이 공평합니다.
3. **"예측구간"을 만듭니다.** 지난 값들로 "다음 값은 이 범위 안에 95%의 확률로 들어올 것"이라는 범위를 계산합니다.
4. 오늘 값이 범위 **밖이면** "평소 범위를 벗어났다"고 표시합니다.

### 왜 t 분포를 쓰나
기록이 몇 개 안 될 때는 "평소 흔들림" 자체를 정확히 알 수 없습니다. 이 불확실성을 반영해서 범위를 **더 넓게** 잡아 주는 것이 **t 분포**입니다. 기록이 많아지면 범위가 자연스럽게 좁아집니다.

> 비유: 동네 식당을 3번 가 보고 "평균 대기 10분"이라고 하는 것과 100번 가 보고 하는 것은 확신이 다릅니다. t 분포는 3번 갔을 때 "10분 ± 많이"라고 말하게 해 줍니다.

### 95%의 뜻
평범한 날이 범위를 벗어날 확률이 5%라는 뜻입니다. 평범한 날의 20번 중 1번은 벗어나는 것이 정상입니다. (그래서 "벗어났다"가 곧 "문제가 있다"는 뜻은 아닙니다)

### 한계
요일 효과가 섞여 있어서 "평소 흔들림"이 실제보다 크게 계산될 수 있습니다. 그러면 범위가 넓어져 오경보는 적지만 진짜 변화를 덜 잡을 수 있습니다(보수적인 방향입니다).

## 3. 내일 예상 매출 (회귀 모형)

### 하는 일
홈의 **"내일 예상 매출"** 카드가 쓰는 계산입니다. 마지막으로 올라온 매출 다음 날의 총매출을 **"얼마와 얼마 사이"라는 범위**로 알려 줍니다. 예: "6만 원 ~ 14만 원 사이일 거예요". 화면에는 범위와 "참고용" 표시만 보이고, 아래 계산 과정은 문서에서만 설명합니다. 평소 기준보다 낫다고 확인되지 않으면 평소 기준으로 범위를 만듭니다.

### 쉬운 설명
**① 로그로 바꿔서 곱셈으로 생각합니다.** 비가 오면 "8,000원 줄어든다"보다 "8% 줄어든다"가 맞는 표현입니다. 매출이 큰 날은 변화도 크기 때문입니다. 그래서 매출에 로그를 취해 계산하고, 마지막에 원래 금액으로 되돌립니다.

```
로그(하루 매출) = 기본값 + 요일 효과 + 장날 + 공휴일 + 방학 + 기온 효과 + 비 온 날 + 남는 차이
```
예: 평범한 수요일이 10만 원이고, 장날이면 ×1.08, 비가 오면 ×0.92라면 100,000 × 1.08 × 0.92 ≈ 99,360원. (가상 숫자)

**② 회귀: 과거 자료에서 "효과"를 찾습니다.** 과거 날마다 실제 매출과 식의 예상이 가장 가깝게 되도록 각 효과의 크기를 고릅니다. 자료가 많을수록 믿을 만한 크기가 나옵니다.

**③ 규제(릿지): 우연한 효과를 누릅니다.** 자료가 적은데 변수가 많으면, 식이 우연한 흔들림까지 효과로 외워 버립니다. 비 온 날이 딱 두 번이었고 그 두 번이 우연히 바빴다면 "비가 오면 매출 증가"라는 엉터리가 나옵니다. 그래서 효과의 크기에 **벌금**을 매겨서, 증거가 확실한 효과만 크게 남고 나머지는 0쪽으로 당겨지게 합니다. 지금 이상치 탐지에서 요일 효과를 0쪽으로 당기는 것과 같은 생각입니다.

**④ 벌금의 세기는 "빼고 맞혀 보기"로 정합니다.** 하루를 빼놓고 나머지로 식을 만들어 그 하루를 맞혀 보는 일을 날마다 반복해서, 가장 잘 맞힌 벌금 세기를 씁니다. (공식으로 한 번에 계산하므로 오래 걸리지 않습니다.)

**⑤ 최근 오차 보정.** 매출 수준이 서서히 달라질 수 있습니다. 그래서 최근 14일 동안 식이 평균적으로 얼마나 빗나갔는지 보고, 그 **절반**만큼 예상을 옮깁니다. (14일과 절반은 시연 자료 하나로 고른 값이라 더 많은 자료에서 다시 확인해야 합니다.)

**⑥ 걸러서 맞혀 보기(백테스트): 정말 낫다고 말할 수 있을 때만 씁니다.** 과거의 어떤 날을 예상할 때 **그날 이전 자료만** 써서 식을 만들고 맞혀 보는 일을 최근 45일에 대해 하루씩 합니다. 같은 방법으로 "평소 기준" 두 가지도 맞혀 봅니다.
- 같은 요일 중간값 (같은 요일 최근 8번의 가운데 값)
- 최근 중간값 (최근 56일의 가운데 값, 요일 구분 없음)

회귀 모형의 **평균 오차가 기준 중 더 잘 맞힌 쪽보다 5% 이상 작고, 보통의 날 오차(중앙값)도 더 나쁘지 않을 때만** 모형을 씁니다. 맞혀 본 날이 15일보다 적으면 판단할 수 없다고 보고 평소 기준을 씁니다.

**⑦ 범위는 과거 오차로 만듭니다.** 걸러서 맞혀 본 오차(실제 ÷ 예상)를 모아서 "10번 중 8번은 이 범위"가 되는 아래·위 끝을 정합니다. 내일 날씨를 **예보**로 쓰면 예보가 틀릴 수 있어서 범위를 10% 더 넓힙니다. 맞혀 본 날이 8일보다 적으면 범위를 말하지 않습니다.

### 날씨는 어디서 오나
- **학습**: 기상청 지상관측(ASOS) 일자료의 **실제 관측값**. 점포에서 가장 가까운 관측소(시흥이라면 약 20km 떨어져 있음)의 평균 기온과 일 강수량입니다. 관측소는 **전국 97곳** 중에서 고르고, 가장 가까운 곳이 **50km보다 멀면 그 날씨는 점포와 많이 달라서 쓰지 않고** 날씨 없이 예상합니다. 비 온 날은 하루 1mm 이상으로 정했습니다.
- **내일 예측**: 기상청 단기예보. 이미 지난 날이면 저장된 관측값을 씁니다. 날씨가 없으면 날씨를 빼고 계산하고 "날씨 정보가 없어요"라고 알립니다.
- **기상특보는 쓰지 않습니다.** 과거 특보를 조회할 수 없어서 학습할 수 없고, 점주와 합의해 고려사항으로만 남겼습니다. ([forecast-considerations.md](forecast-considerations.md) 4장)

### 확인한 결과
**① 실제 23일 (2025-12-23~2026-02-25).** 같은 코드를 돌리면 **평소 기준(최근 중간값)을 씁니다.** 15일을 걸러서 맞혀 보니 모형이 평균 69.7%, 평소 기준 74.6% 빗나갔고, 보통의 날 오차는 모형이 19.1%, 기준이 16.9%였습니다. 모형이 낫다고 말할 수 없습니다. 오차가 큰 이유는 설 연휴 3일입니다. (매출이 평소의 반 이하라 어떤 방법도 크게 틀립니다.)
- 목요일은 한 번도 본 적이 없어서 "요일 효과를 알 수 없어요"라고 알립니다.

**② 시연 자료 (301일, 실제 관측 날씨 + 가정한 효과를 심은 가짜 매출).** 모형이 **되찾았는지** 확인했습니다.

|---|---|---|
| 비 온 날 | −8% | −7.3% ~ −7.9% |

최근 45일을 걸러서 맞혀 보니 모형이 평균 29.1%, 평소 기준(최근 중간값)이 32.3% 빗나가서 **모형을 씁니다.** 보정을 넣기 전에는 모형 33.4%로 평소 기준보다 나쁘지 않을 뿐 낫지는 않았습니다.

- 시연 자료의 마지막 3주에는 일부러 넣은 이상 상황(급감·급증)이 있어서 오차가 커집니다. 이 3주를 빼면 모형 24.4%, 평소 기준 26.3%입니다.

### 왜 이 모형인가 — 다른 방법과 비교

**어떻게 비교했나.** 시드가 다른 시연 자료(가짜) 3개에서 최근 45일을 하루씩, "그날 이전 자료만으로" 예상해 보고 3개의 평균을 냈습니다. 같은 방식으로 여러 모형을 돌렸습니다. 숫자의 뜻은 이렇습니다.
- **평균 오차**: 실제와 예상이 평균 몇 % 어긋났나 (낮을수록 좋음)
- **3주 제외**: 시연 자료 마지막 3주에는 일부러 넣은 급감·급증 상황이 있어서, 그 3주를 뺀 평균 오차
- **보통의 날 오차**: 오차를 줄 세웠을 때 가운데 값 (튀는 날의 영향이 적음)
- **범위 안**: 앞선 날들의 오차로 만든 범위에 실제가 들어온 비율 (목표 80%)
- **범위점수**: 범위가 좁을수록, 실제가 범위 안에 들어올수록 낮아지는 점수 (낮을수록 좋음)

| 모형 | 평균 오차 | 3주 제외 | 보통의 날 | 범위 안 | 범위점수 |
|---|---|---|---|---|---|
| 릿지, 보정 없음 | 31.9% | 26.1% | 25.7% | 72% | 1.31 |
| **릿지, 보정 절반 (앱에서 쓰는 모형)** | **28.7%** | 26.2% | 22.3% | 77% | 1.24 |
| 릿지, 보정 전부 | 26.7% | 26.6% | 20.5% | 78% | 1.21 |
| 릿지 + 최근값(전날·7일·14일 평균) | 30.6% | 26.7% | 25.2% | 75% | 1.25 |
| 강건 회귀(Huber), 보정 절반 | 28.4% | 26.3% | 20.3% | 77% | 1.26 |
| 그래디언트 부스팅 | 30.9% | 28.5% | 23.3% | 70% | 1.30 |
| 랜덤 포레스트 | 30.2% | 27.1% | 21.5% | 74% | 1.33 |
| Holt-Winters (요일 주기, 날씨 없음) | 30.2% | 27.7% | 22.7% | 77% | 1.17 |
| ARIMAX (시계열 + 날씨·달력) | 30.9% | 25.7% | 24.7% | 73% | 1.33 |
| 평소 기준: 최근 중간값 | 30.0% | 26.3% | 25.0% | 73% | 1.28 |
| 평소 기준: 같은 요일 중간값 | 33.6% | 30.2% | 25.6% | 74% | 1.37 |

**읽는 법과 결론**
- **더 복잡한 모형이 이기지 않았습니다.** 부스팅, 랜덤 포레스트, ARIMAX는 앱 모형보다 평균 오차가 약 2%p 큽니다. 자료가 적고 흔들림이 큰데 복잡한 모형은 우연한 흔들림까지 외우기 쉽기 때문입니다.
- **모형끼리의 차이는 대부분 우연의 범위입니다.** 일부러 넣은 상황 3주를 빼면 거의 모두 25.7~28.5%입니다. 이 자료는 하루하루의 흔들림이 커서 약 25%는 어떤 모형으로도 줄일 수 없는 바닥에 가깝습니다.
- **Holt-Winters는 범위점수가 가장 좋지만** 평균 오차는 앱 모형보다 큽니다. 요일 주기만 쓰고 장날·공휴일·날씨를 반영하지 못해서, 점주에게 "왜 이 범위인지" 설명할 수도 없습니다.
- **Huber(튀는 날의 영향을 줄이는 회귀)** 는 보통의 날 오차가 조금 낫지만 범위가 더 넓어져서 바꿀 이유가 못 됩니다.
- **한계:** 시연 자료는 "곱셈으로 작용하는 선형 효과"를 심어서 만들었기 때문에 선형 회귀에 구조적으로 유리합니다. 실제 점포에서 비선형 모형이 나을지는 지금 자료로 알 수 없습니다. 평가한 날이 자료당 35일이라 1~2%p 차이는 우연입니다.

**날씨와 보정은 각각 얼마나 도움이 되나** (릿지 기준, 평균 오차)

| | 보정 있음(절반) | 보정 없음 |
|---|---|---|
| **날씨 있음** | 28.7% | 31.9% |
| **날씨 없음** | 31.3% | 38.6% |

- 보정이 약 7%p, 날씨가 약 2.6%p를 줄입니다. **개선의 대부분은 날씨가 아니라 보정(매출 수준이 달라지는 것을 따라가는 일)에서 나옵니다.** 시연 자료에 심은 날씨 효과(기온 1도당 +0.6%, 비 −8%)가 하루의 흔들림(약 25%)에 비해 작기 때문입니다.

### L1(라쏘)과 L2(릿지)를 비교한 이유

**규제의 두 종류.** 릿지(L2)는 계수의 **제곱**의 합에, 라쏘(L1)는 계수의 **절댓값**의 합에 벌금을 매깁니다. 라쏘는 벌금이 커지면 일부 계수를 **정확히 0**으로 만들어 변수를 지워 버리고, 릿지는 모든 계수를 작게나마 남깁니다. 두 방식을 섞은 것이 엘라스틱넷입니다.

| 규제 | 평균 오차 | 3주 제외 | 보통의 날 | 범위 안 | 범위점수 |
|---|---|---|---|---|---|
| **릿지 L2 (앱)**, 보정 절반 | 28.7% | 26.2% | 22.3% | 77% | 1.24 |
| 라쏘 L1, 보정 절반 | 28.7% | 26.1% | 22.7% | 78% | 1.25 |
| 엘라스틱넷 L1+L2, 보정 절반 | 28.7% | 26.1% | 22.6% | 78% | 1.25 |
| 라쏘 L1, 보정 없음 | 32.0% | 26.1% | 25.7% | 74% | 1.33 |

**결론: 성능이 같아서 L2를 씁니다.** L1을 쓰지 않는 이유는 성능이 아니라 쓰임새입니다.
- **지워진 효과는 "효과가 없다"로 읽힙니다.** 라쏘는 변수 11개 중 평균 4.7개를 0으로 만들었습니다. 점주에게 "비 온 날 효과 0%"는 "비가 와도 매출이 안 변한다"로 들리지만 실제 뜻은 "증거가 부족하다"입니다.
- **서로 얽힌 변수에서 선택이 불안정합니다.** 방학, 기온, 연휴는 겨울에 같이 움직입니다. L1은 이런 변수들 중 아무거나 하나를 고르고 나머지를 지웁니다. 자료가 조금만 바뀌어도 선택이 달라질 수 있고, L2는 효과를 나눠 갖게 해서 안정적입니다.
- **변수가 11개뿐입니다.** L1의 장점은 변수가 수십~수백 개일 때 필요한 것만 골라내는 것인데 여기서는 필요하지 않습니다.
- **구현이 간단합니다.** 릿지는 공식으로 풀려서 "하루를 빼고 맞히기"도 한 번에 계산됩니다. L1은 반복 계산과 별도 라이브러리가 필요합니다.
- (L3 규제는 일반적으로 쓰지 않는 방법이라 비교하지 않았습니다. p가 1, 2인 경우만 널리 쓰입니다.)

### 정한 값들을 왜 이렇게 정했나

| 값 | 정한 방법 | 이유 |
|---|---|---|
| **로그를 취함** | 이론에 따름 | 날씨·장날 효과는 "몇 원"이 아니라 "몇 %"로 작용하기 때문 |
| **월요일이 기준 요일** | 관례 | 요일 효과는 기준이 되는 요일과의 차이로 표현해야 해서 하나를 빼야 하고, 어느 요일이든 결과는 같음 |
| **변수를 같은 눈금으로 맞춤(표준화)** | 이론에 따름 | 기온(−10~30)과 비 온 날(0/1)처럼 단위가 다른 변수에 벌금이 공평하게 매겨지도록 |
| **벌금 세기 λ** | **자료에서 정함** | {0.5, 2, 5, 10, 20, 50, 100} 중 "하루를 빼고 나머지로 맞혀 보는" 오차가 가장 작은 값. 후보 범위 자체는 사람이 정함. 값이 너무 작으면 우연한 효과가 커지고 너무 크면 효과가 모두 사라지는 구간을 덮도록 잡음 |
| **최근 오차 보정: 최근 14일, 절반** | **시연 자료 하나로 골랐음** | 아래 표 참고. 중간 값을 택함 |
| **모형 채택 기준: 평균 오차가 5% 이상 작고 보통의 날 오차도 안 나쁨** | 사람이 정함 | 작은 차이는 우연일 수 있어서 여유를 두었음. 5%는 근거 있는 값이 아니라 보수적인 선택 |
| **걸러서 맞혀 보는 기간 45일** | 사람이 정함 | 약 6주. 너무 짧으면 판단이 흔들리고, 너무 길면 계절 변화가 섞임 |
| **모형을 판단하려면 맞혀 본 날 15일, 범위를 말하려면 8일** | 사람이 정함 | 그보다 적으면 비교·범위가 우연에 좌우됨 |
| **학습을 시작하는 최소 일수 28일 (자료 40일 미만이면 8일)** | 사람이 정함 | 요일·달력·날씨 변수를 처음 추정하는 데 필요한 최소 분량 |
| **예상을 시작하는 최소 일수 12일** | 사람이 정함 | 이보다 적으면 "데이터가 더 필요해요" |
| **평소 기준: 같은 요일 최근 8번 (3번 미만이면 최근 56일 중앙값)** | 기존 앱의 규칙에 맞춤 | "같은 요일 3번 이상이어야 비교한다"는 홈의 기존 규칙과 같음 |
| **범위: 10%~90% 지점 (10번 중 8번)** | 관례 | 95% 범위는 너무 넓어서 쓸모가 적고, 50%는 자주 벗어남 |
| **예보 날씨를 쓰면 범위 ×1.1** | **임의의 값 (근거 없음)** | 예보가 틀릴 수 있다는 점을 반영하려고 넣었지만 크기는 사람이 정한 값 |
| **비 온 날 = 하루 강수량 1mm 이상** | 관례 | 이슬비를 제외하고 의미 있는 비만 "비 온 날"로 보려는 값 |
| **관측소가 50km보다 멀면 날씨를 쓰지 않음** | **가정값(제 판단)** | 멀수록 같은 날 비가 오고 안 오는 것이 달라진다는 상식. 거리별 정확도는 확인하지 않았습니다. (지금 기준으로 독도·가거도·연평도처럼 섬이나 외딴 곳이 여기에 걸립니다) |
| **가장 가까운 관측소** | 거리 계산 | 점포 위치와 관측소 위치 사이 거리 |

**최근 오차 보정 14일·절반을 고른 근거 (시연 자료 하나, 최근 45일, 평균 오차 / 보통의 날 오차)**

| 보정 | 최근 며칠 | 전체 45일 | 일부러 넣은 상황 3주 제외 |
|---|---|---|---|
| 없음 | | 33.4% / 29.3% | 23.7% / 15.6% |
| 절반 | 7일 | 27.8% / 21.3% | 23.5% / 18.3% |
| **절반** | **14일** | **29.1% / 22.2%** | **24.4% / 15.8%** |
| 절반 | 28일 | 31.1% / 24.5% | 24.3% / 16.2% |
| 전부 | 7일 | 25.2% / 18.8% | 24.2% / 18.7% |
| 전부 | 14일 | 26.7% / 19.0% | 25.5% / 18.2% |
| 전부 | 28일 | 29.8% / 22.4% | 25.4% / 18.0% |
| (참고) 평소 기준: 최근 중간값 | | 32.3% / 23.8% | 26.3% / 17.5% |

- **보정을 넣는 것**은 효과가 분명합니다(33.4% → 29% 안팎). 일부러 넣은 상황이 있는 마지막 3주에서 특히 그렇습니다.
- **세게 반영할수록, 최근 며칠만 볼수록** 전체 오차는 더 줄지만, 상황이 없는 구간(3주 제외)에서는 오히려 조금 나빠지거나 같습니다. 최근 며칠의 우연한 흔들림을 그대로 따라가기 때문입니다.
- 그래서 **너무 둔하지도(28일) 너무 예민하지도(7일) 않은 14일과, 반영을 전부가 아닌 절반**으로 한 중간 선택을 했습니다. 이것은 **시연 자료 하나로 고른 값**이라, 실제 자료가 쌓이면 같은 비교를 다시 해서 점검해야 합니다.

### 믿어도 되는 것과 안 되는 것
- **믿어도 됨**: 모형이 평소 기준보다 낫지 않을 때는 쓰지 않는다는 안전장치. 심은 효과를 찾아내는 코드의 동작. 범위가 과거 오차에서 나온다는 점.
- **믿으면 안 됨**: 실제 점주의 날씨 효과 크기(자료 없음). 시연 자료의 오차율(가짜 자료라 실제 예측 정확도가 아님). 보정 14일·절반 같은 값(자료 하나로 고른 값).
- **모형에 없는 것**: 행사·판촉, 공사, 갑작스러운 휴업, 기상특보, 예보가 틀린 정도.
- 관측소가 점포에서 20km쯤 떨어져 있어 같은 날도 비가 오고 안 오는 것이 다를 수 있습니다. (예: 어느 날 수원 12.3mm, 서울 6.5mm, 인천 6.1mm)
- 방학과 기온은 겨울에 같이 움직여서 한 해 안에서는 둘의 효과를 완전히 나눌 수 없습니다. 규제가 두 효과에 나눠 담습니다.

## 4. 주변 상권 판단 (학생·직장인·주거·교통)

### 하는 일
홈의 "AI 제안"이 "이 동네는 학생 손님이 많은 곳이에요", "사는 사람이 많은 동네예요"처럼 **동네의 성격**을 말할 수 있게, 코드가 공개 자료로 간단한 기준을 적용해 판단합니다. 판단은 AI가 아니라 **코드가 정해진 기준**으로 하고, AI는 그 결과를 문장으로 풀어 쓰기만 합니다.

### 쉬운 설명
복잡한 통계 모형이 아니라 **"숫자 하나를 기준선과 비교하는 규칙"**입니다. 동네 소개를 할 때 "이 동네는 학교가 많아요", "일하러 오는 사람이 사는 사람보다 많아요"라고 말하는 것과 같습니다. 다만 규칙의 기준선(예: 학원 5곳)은 **통계로 구한 값이 아니라 제가 정한 가정값**이라서, 틀릴 수 있다는 점을 늘 같이 말합니다.

| 판단 | 비교하는 것 | 기준선 | 예 (가상 숫자) |
|---|---|---|---|
| 학생 상권 | 반경 500m 안 학교 수, 점포 바로 앞 100m 안 학원 수 | 학교 1곳 이상 **또는** 학원 3곳 이상 | 학교 2곳, 학원 25곳 → 학생·수강생 손님의 영향을 받을 수 있는 상권 |
| 직장인 상권 | (일하는 사람 수) ÷ (사는 사람 수) | 1.0 이상이면 직장인 상권, 0.5 이상 1.0 미만이면 "직장인도 있는 동네" | 일하는 사람 8,000명 ÷ 사는 사람 20,000명 = 0.4 → 해당 없음 |
| 주거 상권 | 위와 같은 비율 | 0.5 미만(사는 사람이 일하는 사람의 두 배 넘음). 가구당 평균 2.2명 이하면 "1~2인 가구가 많은 편"을 덧붙임 | 0.4이면 주거 중심, 가구당 1.8명이면 1~2인 가구가 많은 편 |
| 교통 상권 | 반경 500m 안 지하철역 수 | 1곳 이상 | 역 2곳 → 출퇴근·통학으로 오가는 손님의 영향 |
| 동네 연령 구성 | 연령대별 인구 ÷ 연령대 합 | (판단이 아니라 비율 계산) | 20대 3,256명 ÷ 연령대 합 23,929명 = 14% |

- **학원**: 점포 바로 앞 100m 안에 학원이 3곳 이상이면 학교가 없어도 학생 상권으로 봅니다. 한두 곳은 어느 동네에나 있어서 동네의 성격을 말해 주지 못한다고 보았기 때문입니다.
- **일하는 사람 ÷ 사는 사람**: 통계청이 집계한 "그 동네 사업체에서 일하는 사람 수(종사자)"를 "주민등록상 그 동네에 사는 사람 수"로 나눕니다. 값이 클수록 낮에 일하러 오는 사람이 많은 동네(사무실 거리)이고, 작을수록 사는 사람이 많은 동네(주택가)입니다.
- **대학 방학**: 공식 자료가 없어서 "많은 대학이 6월 21일~8월 31일, 12월 21일~2월 28일에 쉰다"는 **일반적인 달력 어림**을 쓰고, 항상 "학교마다 달라요"를 붙입니다.

### 왜 이 방법인가
- 점주님 매출 자료가 아직 23일뿐이라, 매출로 "이 동네는 학생 손님이 많다"를 **확인할 수 없습니다.** 그래서 공개 자료(학교·학원 수, 통계청 인구)로 만든 **일반적인 추정**을 하고, 그 사실을 AI에게 줍니다.
- 모형을 쓰지 않고 간단한 기준선을 쓴 것은, 점주님이 "왜 이런 말을 하지?"를 바로 확인할 수 있게 하려는 것입니다. (숫자 두 개와 기준선만 보면 됩니다.)

### 정한 값과 근거
| 값 | 종류 | 근거 |
|---|---|---|
| 100m 안 학원 3곳 | **가정값(제 판단)** | 한두 곳은 흔해서 성격을 말하기 어렵다는 생각. 공개 자료로 확인한 값이 아님 |
| 직장인 1.0, 직장인도 있음 0.5, 주거 0.5 | **가정값(제 판단)** | "일하는 사람이 사는 사람보다 많으면 사무실 거리"라는 상식에서 정함. 실제 지역들을 눌러 보며 조정할 값 |
| 1~2인 가구 2.2명 | **가정값(제 판단)** | 전국 평균 가구원 수(약 2.2명 안팎)보다 작거나 같으면 1~2인 가구가 많다고 봄. 정확한 전국 평균은 확인하지 않음 |
| 지하철역 1곳 | 가정값 | 있으면 통근·통학 이동이 생긴다는 상식 |
| 반경 500m | 가정값 | 걸어서 5~7분 거리 |
| 대학 방학 날짜 | 가정값 | 많은 대학의 일반적인 학사 일정. 학교마다 다름 |

통계로 구한 값은 없습니다. 모두 사람이 정한 기준입니다. 그래서 실제 점포의 매출 자료가 충분히 쌓이면 "학생 상권으로 판단한 날과 아닌 날의 매출이 정말 다른지"를 확인해서 기준을 고쳐야 합니다.

### 믿어도 되는 것 / 안 되는 것
- **믿어도 되는 것**: 반경 안의 학교·학원·지하철역 **개수**(카카오 검색 결과), 동네의 인구·연령·종사자 **숫자**(통계청). 숫자 자체는 공개 자료 그대로입니다.
- **안 되는 것**:
  - "학생 상권이다", "주거 중심이다"라는 **해석**은 이 점포의 매출로 확인한 것이 아닙니다. 그래서 문장에 항상 "일반적인 추정"이 붙고, AI도 "~일 수 있어요"로만 말합니다.
  - 인구는 **그 동네에 사는 사람** 기준이라 오가는 사람과 직장인은 빠집니다. (서울 명동 같은 상권은 사는 사람이 2,500명뿐이라 실제 유동과 크게 다릅니다.)
  - 동 단위 숫자라 점포 반경 500m와 범위가 다릅니다.
  - 연령대별 숫자를 더하면 총인구와 0.7% 정도 어긋날 수 있어서, 비율은 연령대 합을 기준으로 냅니다.
  - 학원 수에는 어학원·운전학원 같은 성인 대상도 섞여 있습니다.
  - 편의점 수에는 우리 점포가 들어 있을 수 있습니다.

## 5. 용어 사전

| 용어 | 쉬운 뜻 |
|---|---|
| 시계열 | 시간 순서대로 쌓이는 숫자 (매일의 매출 등) |
| 이상치 (이상) | 평소와 많이 다른 값 |
| 하루짜리 튐 (점 이상) | 하루만 평소와 다른 것 |
| 이어지는 변화 (수준 이동) | 어느 시점부터 평소 수준이 달라져서 이어지는 것 |
| 중앙값 | 크기순으로 줄 세웠을 때 한가운데 값. 튀는 값에 강함 |
| 평균 | 모두 더해서 개수로 나눈 값. 튀는 값에 약함 |
| 표준편차 | 값들이 평균에서 평균적으로 얼마나 떨어져 있나 (흩어진 정도) |
| MAD | 중앙값에서 떨어진 정도의 중앙값. 튀는 값에 강한 "흩어진 정도" |
| 로그 | 차이를 "몇 원"이 아니라 "몇 배"로 보게 바꾸는 변환. 곱셈을 덧셈으로 바꿔 주기도 함 |
| 요일 효과 | 요일마다 평소 수준이 다른 것 (월요일은 높음 등) |
| 잔차 | 요일 효과 등 "예상한 부분"을 빼고 남은 차이 |
| 점수 (z) | 평소에서 떨어진 정도를 "흔들림의 몇 배"로 나타낸 숫자 |
| Shewhart | 하루 점수가 기준을 넘으면 알리는 방식 (공장 품질 관리 출신) |
| CUSUM | 매일의 차이를 누적해서 기준을 넘으면 알리는 방식. 이어지는 변화에 강함 |
| 허용치 k | CUSUM에서 "이 정도 차이는 변화로 치지 않겠다"는 크기 |
| 기준 h | CUSUM의 누적이 이 값을 넘으면 알림 |
| 민감도 | 알림이 얼마나 잘 나는지. 높을수록 작은 변화에도 알림이 나고 알림이 늘어남 |
| 오경보 | 이상이 아닌데 이상이라고 올린 것 |
| t 분포 | 데이터가 적을 때 불확실성을 반영해서 범위를 넓혀 주는 분포 |
| 예측구간 | "다음 값이 이 범위에 들어올 것"이라는 범위 (예: 95%) |
| 가정값 | 실제 근거 없이 사람이 정한 숫자 |
| 회귀 | 여러 요인(요일, 날씨 등)이 매출에 주는 효과의 크기를 과거 자료에서 찾는 방법 |
| 릿지(규제) | 효과의 크기에 벌금을 매겨 우연한 효과가 커지지 않게 하는 회귀 |
| 벌금(λ) | 릿지에서 효과를 얼마나 세게 누를지. 자료에서 "빼고 맞히기"로 고름 |
| 빼고 맞히기 | 하루를 빼고 나머지로 만든 식으로 그 하루를 맞혀 보는 것 |
| 걸러서 맞혀 보기 (백테스트) | 과거의 날을 그날 이전 자료만으로 예상해 보고 실제와 비교하는 것 |
| 최근 오차 보정 | 최근 며칠 식이 빗나간 만큼 예상을 옮겨 매출 수준의 변화를 따라가는 것 |
| 라쏘 (L1 규제) | 계수의 절댓값에 벌금을 매겨 일부 효과를 0으로 지우는 회귀 |
| 릿지 (L2 규제) | 계수의 제곱에 벌금을 매겨 모든 효과를 작게 남기는 회귀 (앱에서 쓰는 방식) |
| 범위점수 | 범위가 좁을수록, 실제가 범위 안에 들어올수록 낮아지는 점수 (낮을수록 좋음) |
| 종사자 | 그 동네 사업체에서 일하는 사람 (사는 곳과 상관없이 일하는 곳 기준) |
| 거주 인구 | 주민등록상 그 동네에 사는 사람 (오가는 사람은 빠짐) |
| 기준선 | 숫자 하나를 "많다/적다"로 가르는 경계값. 이 앱의 상권 판단 기준선은 사람이 정한 가정값 |

## 추가하는 법 (통계가 들어간 작업을 할 때)

새로운 통계적 방법(예측 모델, 새 탐지 기준, 표본 크기 계산 등)을 쓰면 이 문서에 **새 번호의 장**을 만들어 아래를 적습니다.

1. **하는 일** — 어떤 화면/기능에서 무엇을 위해 쓰는가
2. **쉬운 설명** — 통계 용어 없이, 가능하면 비유와 작은 예시로. **시계열 이상치 탐지처럼 판단 규칙이 있는 방법은 가상 숫자로 "어떻게 판단하는지"를 한 번 따라가 봅니다.**
3. **왜 이 방법인가** — 대안 대신 이걸 고른 이유
4. **정한 값과 근거** — 통계로 구한 값인지, 사람이 정한 가정값인지 구분
5. **믿어도 되는 것 / 안 되는 것** — 한계
6. 새 용어는 용어 사전에 추가하고, 목차와 맨 위 "앱에 반영됨 / 실험 중" 표도 갱신

정확한 계산식은 calculation.md에 쓰고, 이 문서에는 **쉬운 설명**만 둡니다.
